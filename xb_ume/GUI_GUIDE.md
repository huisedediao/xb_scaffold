# xb_ume GUI 工具箱使用指南

> 电脑端调试助手：设备管理、守护进程管理、手机日志实时查看、路由/网络/日志/异常统一时间轴。
> 零新增依赖、无需编译，随 `dart run xb_ume:ide --install` 一并安装。

## 一、启动方式（三选一）

### 方式 1：命令启动（推荐）

```bash
# 在依赖 xb_ume 的项目目录中
dart run xb_ume:ide --gui
```

### 方式 2：双击桌面入口（安装时自动创建）

`--install` 会在系统常用位置创建 GUI 桌面入口：

| 平台 | 入口位置 | 打开方式 |
|---|---|---|
| macOS | `/Applications/xb_ume 工具箱.app`（若无写权限则装到 `~/Applications`） | 在「应用程序」文件夹双击，或 Launchpad / Spotlight 搜索「xb_ume」；卸载时一并删除 |
| Windows | 桌面快捷方式「xb_ume 工具箱.lnk」 | 双击后 GUI 以最小化窗口运行在任务栏（图标为 dart 图标），页面自动弹出；卸载时一并删除 |

保留的备用启动器（隐藏目录 `~/.xb_ume_ide/` 内）：macOS `xb_ume_gui.command`（Finder 按 `Cmd+Shift+G` 输入 `~/.xb_ume_ide` 直达，首次被 Gatekeeper 拦截时右键 → 打开）；Windows `XBumeGui.bat`。

### 方式 3：直接运行部署副本

```bash
dart ~/.xb_ume_ide/ide_gui.dart    # macOS
dart %USERPROFILE%\.xb_ume_ide\ide_gui.dart   # Windows
```

### 启动行为

- 启动后自动打开浏览器访问 `http://127.0.0.1:46129`（端口被占用时自动顺延）；
- **单实例**：已有 GUI 在跑时，再次启动只会新开一个浏览器页面，不会出现多个实例；
- 桌面入口 / `.command` / `.bat` 都是「一键开启」：先 `--ensure-daemon`（守护进程没跑就拉起来，已在跑则什么都不做）再起 GUI；
- 服务进程窗口保持开启即页面可用，关闭窗口（或 Ctrl-C）即退出 GUI；不关窗口也能在页头「服务」菜单里重启 / 停止（见下文「服务控制」）。

### 本地访问令牌

GUI 只监听 `127.0.0.1`，并校验 `Host` / `Origin`，防止任意网页或 DNS rebinding 访问本机调试接口。启动时会生成一次性访问令牌：

- **浏览器页面**：打开根页面时自动下发 `HttpOnly + SameSite=Strict` Cookie，页面内 `fetch` 与 WebSocket 自动携带，无需手工处理；GUI 重启后令牌会重建，旧标签页点任意按钮会自动重载一次（异常情况下手动刷新页面即可）。
- **本地脚本 / CLI**：读取 `~/.xb_ume_ide/gui.token`（macOS/Linux 权限 `600`），请求头带 `X-XBUME-Token: <token>`；WebSocket 也可用 `ws://127.0.0.1:<端口>/ws?token=<token>`。
- 令牌每次启动都会更新，请勿写入共享脚本或提交到仓库。

## 三、功能详细使用说明

### 服务控制（页头右侧「服务」菜单）

**功能**：不用回终端就能重启 / 停止 / 开启 GUI 与守护进程，改了 `bin/` 下的脚本也能一键重新部署。入口在页头右侧：两个徽标分别显示 GUI 与 daemon 的状态（绿色=在跑：GUI 显示端口、daemon 显示已接入会话数；红色 `○`=未运行），每 5 秒自动刷新。

**菜单项**：

| 菜单项 | 行为 | 备注 |
|---|---|---|
| 重启 GUI | 新实例先起来接班 → 旧实例优雅退出（先关掉所有 VM 会话再退）→ 新实例抢回原端口 | 3~5s，页面出现「重启中」遮罩并轮询 `/ping`，恢复后自动刷新页面；调试中的 app 不会因断连卡死 |
| 重启守护进程 | macOS 走 `launchctl kickstart -k`（原地重启，不会出现两个实例抢端口）；其他平台按精确 PID 结束后重新拉起 | 2~6s；Tab「守护进程」的「重启守护进程」按钮是同一套实现 |
| 重启全部 | 先守护进程、后 GUI | 5~10s；顺序固定，页面恢复后 daemon 已在跑 |
| 停止 GUI | 优雅退出（同上），页面停在「服务已停止」遮罩 | 页面不会自己回来：双击「xb_ume 工具箱」或 `dart run xb_ume:ide --gui` 再开 |
| 停止守护进程 | macOS 用 `launchctl bootout` 卸下 LaunchAgent（`KeepAlive` 不会再拉回来）；其他平台按精确 PID 结束 | 双击工具箱启动时会 `--ensure-daemon` 顺手拉起 |
| 重新部署并重启 | 从 `--install` 时记下的源码目录重跑一遍安装，等旧 GUI 退出后新副本启动 | 10~60s；进度与失败原因看「查看部署日志」。没记录过源码目录时该项置灰并提示先跑 `--install` |
| 查看部署日志 | 打开浮层查看 `~/.xb_ume_ide/install.log` 尾部 | 只读增量拉取，不阻塞页面 |

**使用步骤**：

1. 点页头「服务 ▾」选动作，破坏性动作（停止 / 重启）会先弹一次确认；
2. 动作执行期间按钮显示「执行中…」，同一时刻只跑一个（避免「重启」和「停止」互相踩）；
3. 「重启 GUI / 全部」后页面自动重连并刷新；「停止」后页面提示已停止，按需双击工具箱恢复。

**不开页面也能操作**（CLI 兜底，输出以 `[xbume-svc]` 开头）：

```bash
dart run xb_ume:ide --svc status             # GUI / 守护进程 / 源码目录三行摘要
dart run xb_ume:ide --svc restart daemon     # gui / daemon / all 三选一，默认 all
dart run xb_ume:ide --svc stop gui
dart run xb_ume:ide --svc start all
dart run xb_ume:ide --svc redeploy           # 需 GUI 在跑
dart run xb_ume:ide --ensure-daemon          # 幂等：没跑就拉起
```

GUI 在跑时，`--svc stop gui` / `restart` / `redeploy` 会把请求转给页面进程（带令牌的 `POST /api/svc/...`），所以也会走优雅退出；GUI 没在跑时直接控制守护进程。

### 1. 设备管理（页头右侧，全局）

**功能**：自动发现连接到电脑的手机/模拟器，可选中一台。位于页头右侧，不随 Tab 切换。

**支持的平台与工具依赖**：

| 平台 | 发现方式 | 依赖 |
|---|---|---|
| Android（真机/模拟器） | `adb devices -l` | Android 平台工具（flutter 开发环境一般已具备） |
| 鸿蒙（真机/模拟器） | `hdc list targets` | HarmonyOS SDK 的 hdc 命令 |
| iOS 模拟器（仅 macOS） | `xcrun simctl list devices booted` | Xcode |
| iOS 真机（仅 macOS） | `idevice_id -l` | `brew install libimobiledevice`（未装则不显示） |

**使用步骤**：

1. 手机用数据线连上电脑（模拟器/无线调试同理）；
2. 打开页头右侧的设备下拉框（列表每 3 秒自动刷新，也可点旁边「刷新」立即扫描）；
3. 在下拉框中选中设备——选中后「日志」Tab 的设备日志源即切到该设备；下拉项尾部括号内为设备状态；
4. 状态列含义：`device`（绿色，正常）/ `offline`、`unauthorized`（红色，需在手机上允许 USB 调试或重插）；
5. 设备拔出后日志源自动停止，重新插入自动恢复。

### 2. 守护进程管理（Tab「守护进程」）

**功能**：查看与管理 IDE 跳转功能的常驻守护进程（daemon）。

**状态卡片**展示：

- 运行状态：`运行中`（绿色，含 pid 与已运行时长）/ `未运行`（红色）；
- 已接入的调试会话列表：每条为「来源 → VM service 地址」，即当前连着哪些 `flutter run` 会话；
- IDE 优先级：可拖拽排序的列表（每项前有 ☰ 拖动标识），拖完自动保存到 `~/.xb_ume_ide/config.json` 的 `ideOrder`；未安装的 IDE 灰色标注「未安装」（daemon 唤起时自动跳过）；

**使用步骤**：

- **查看状态**：进入 Tab 自动查询，或点「刷新」；
- **重启守护进程**：点「重启守护进程」→ 确认弹窗 → 自动重启（macOS 走 `launchctl kickstart -k` 原地重启；其他平台按精确 PID 结束后重新拉起）并等待就绪，成功后显示新状态。适用场景：修改配置后不生效、daemon 行为异常、升级脚本后刷新实例。正在调试的会话断开后会自动重连，无需重启 `flutter run`；页头「服务 → 重启守护进程」是同一套实现；
- **修改 IDE 优先级**：拖动条目前面的 ☰ 到目标位置，松手即保存（daemon 每次跳转时重读，立即生效）；每次进入本页会自动扫描本机已安装的 IDE，新装的自动追加到列表末尾并写回配置（已在配置中、后来卸载的仍保留并标注「未安装」）；「恢复默认」一键写回完整默认名单；也可点「打开配置文件」用系统编辑器改。

**MCP 服务卡片**（同一 Tab，在守护进程状态下方）：

展示本机 MCP 服务的运行状态，让 Qoder / Cursor / Claude Code 等客户端直接驱动调试会话：

- `未运行`（红色）：下方给出启动命令（`dart run xb_ume:mcp` 或 `--http 46140`）；
- `运行中 · HTTP <端口> · <N> 个工具`：探测经 `initialize` + `tools/list` 握手得到，同时列出访问地址、协议版本（仅本机回环，需 token）；
- `运行中 · stdio · pid <pid>`：stdio 模式没有监听端口，只能按进程命令行识别，工具数在客户端会话里可见；
- **复制 MCP 配置**：按当前运行状态生成可直接粘贴的客户端配置（stdio → `command/args`；HTTP → `url` + `X-XBUME-Token`），剪贴板被浏览器拦下时配置会同时展开在下方可手动选中；
- **启动 / 停止**：点「启动」后台拉起 `~/.xb_ume_ide/mcp.dart --http <46140-46149 首个空闲> --pool-entry --tool-groups all`（日志写 `~/.xb_ume_ide/logs/mcp.log`），点「停止」结束这个进程；重复启动是幂等的，不会起第二个实例。只停工具箱自己拉起的进程（pid 记在 `~/.xb_ume_ide/mcp.pid`），客户端以 stdio 拉起的要去客户端里关；
- **服务池**：无名启动的默认服务是一个池入口（`--pool-entry`） ，客户端只连它一个地址，入口按连接给每个窗口分配后端实例——空闲槽杀掉残留进程后拉起全新实例、没满就拉起、5 个都绑着就回「需要排队」。卡片下方列出 5 个槽：谁绑着（实例名 / 客户端名 /  绑定标识 `b-xxxxxx`）、在干什么、还剩多久，每行可「释放并停实例」（绑定释放 + 按精确 pid 结束该 worker）；槽里跑着自动化时显示「跑着场景」、暂不回收。绑定 10 分钟不续期自动回收（连实例一起停，重绑是全新进程），入口每 30 秒扫一遍池；AI 侧用 `xbume_pool` 查看 / 释放 / 接管；具名实例（「新建实例」起的）仍是普通 worker，不参与分配；
- **能力范围**：`--tool-groups all` 一次开 58 个工具——默认 29 个（core 22 / diagnose / run-safe）+ `act` / `device-write`（设备操作，高危需 `confirm`）+ `debug`6（断点、单步、调用栈、变量、运行输出，直连 VM，不依赖 GUI）+ `inspect`4（Widget 树、实例、性能/泄漏、双会话对比）+ `data`4（shared_prefs、SQLite、沙盒文件、表达式监听）+ `env`8（IDE 跳转、守护进程、路由定位、时间轴、GUI 日志历史、网络重放、异常 AI 归因、自动化）+ `ai`1（自然语言驱动）；后四组走 GUI 的 HTTP 接口，需要工具箱在跑。工具数由卡片的 `tools/list` 握手实时统计，重启服务后自动更新；
- **随工具箱启动**：勾上后每次打开工具箱自动拉起 MCP（写在 `config.json` 的 `mcpAutoStart`，默认关）；勾上时若服务未运行会立即拉起，取消勾选不会停掉正在跑的服务。

注意：MCP 服务默认不开（没人调就不跑），也不随系统开机自启；需要时点「启动」、勾上「随工具箱启动」，或让客户端以 stdio 方式拉起（推荐）。工具清单与完整配置见 [MCP_GUIDE.md](MCP_GUIDE.md)。

### 3. AI 调试（Tab「AI 调试」）

**功能**：给「让 AI 自己调试 app」准备的零学习入口。一个动作把三件事做完：确保带 `xbume_eval` 的 MCP 在跑 → 按项目目录 + 设备生成一段可直接粘给 AI 的指令 → 指令写进剪贴板。不用先学 MCP、`--allow-eval`、token 这些东西。

**使用步骤**：

1. 打开 Tab（或直接访问 `http://127.0.0.1:<gui 端口>/#ai`，深链与手动点击行为一致）；
2. 「项目目录」可以直接选：点输入框旁的「选择…」弹出目录选择器，从本机目录里点进去找项目根（Flutter 项目带标记并排在前面，底部会提示当前目录有没有 `pubspec.yaml`），确认后点「选定此目录」；也可以从下拉候选里选（候选 = 当前已连接的调试会话反推的项目根 + 最近用过的目录），或直接粘路径。只需选一次，之后记在 `config.json` 的 `aiProjectDir` / `aiRecentDirs`。「设备」是下拉选择：自动（唯一手机 > 本机桌面 > 首个可用）/ 具体手机 / 本机桌面（macOS 为 `macOS 桌面`，Windows 为 `Windows 桌面`），默认跟随右上角设备选择器；
3. 点「一键开启」→ 状态变成 `已就绪 · N 个工具 · eval 已开 · 指令已复制`；
4. 「复制 AI 指令」随时再取；「复制 MCP 配置」生成当前服务的客户端配置（HTTP 自动带 token），第一次接 AI 客户端时粘它。

> **和右上角「VM 会话」的关系**：右上角选的是**已经在跑**的 app 会话，供日志/时间轴/路由等 Tab 用；**AI 调试会优先复用它们**。会话列表里带 `launcher` 标记（`mcp拉起` / `gui认领`）且标了 `·可热重载` 的，AI 直接 `xbume_use_session` 接上就能热重载，不会重装包；只有 `·只读` 和 IDE / 终端拉起的会话拿不到输入句柄——能看界面、下断点、eval、看时间轴，热重载要回 IDE 按 `r`，或让 AI 问你之后用 `force: true` 重启接管（手机上会顶掉 IDE 的调试会话）。两者的信息也互相利用：AI 调试页会把当前会话的项目根（按 app 的库路径反推）作为项目目录候选，设备也会默认跟随右上角选择。

**它会做什么（以及不做什么）**：

- 服务已在跑且带 eval：直接复用，不重启；
- 在跑但没有 eval：只重启**自己 pid 记录的那个**（`~/.xb_ume_ide/mcp.pid`）；不是工具箱拉起的服务会明确拒绝，让你手动处理；
- 没在跑：后台拉起 `~/.xb_ume_ide/mcp.dart --http <46140-46149 首个空闲> --tool-groups all --allow-eval`（不改 `config.json` 的 `mcpAllowEval`）；
- **不代劳拉起 app**：指令里写明让 AI 调 `xbume_app_launch(via: "flutter-run", cwd: "<项目路径>")`——flutter run 的 stdin 在 MCP 进程手里，`xbume_hot_reload` 才有句柄；外部终端里已在跑的 `flutter run` 怎么处理见下一条；
- **不会默默顶掉 IDE 的会话**：`xbume_app_launch` 发现**同设备 + 同目录**已有 `flutter run`（比如 IDE 里起的）时**默认拒绝启动**并报出那个 pid——继续会在手机上重装包、IDE 报「Lost connection」。要么复用现有会话（`xbume_sessions` → `xbume_use_session`，无热重载），要么明确传 `force: true`；
- 剪贴板被浏览器策略拦下时，状态行会提示改用「复制 AI 指令」手动全选。

命令行等价：`dart run xb_ume:ai`（`--dir` / `--device` / `--print-only` / `--json`），与 Tab 共用同一套逻辑。

### 4. 调试（Tab「调试」）

**功能**：类是 IDE 的调试面板——起停 app、打断点、暂停/单步、看栈与变量、热重载/热重启，全在网页里完成。app 端零改动，只走 VM service，**源码只读展示（不做语法高亮）、不改代码**（断点只认「文件 + 行号」，不需要在项目里装任何东西）。

**版式（参考 VS Code 调试视图）**：一屏装下，不再上下堆卡片、整页跟着滚。顶部是工具条（会话状态 / 项目目录 / 设备 / 入口 / 启动 / 运行配置 / 接入会话）；下面三栏：**左栏** 断点 / 路由栈 / 已记住，**中栏** 调用栈 + 变量 + 求值（变量树占满剩余高度），**右栏** 源码（点「源码下断点」才出现，关掉时中栏自动变宽）；**底部** 运行输出（默认 `clamp(170px,26vh,300px)`；拖卡片上沿可调高、双击手柄复位，高度会记住；标题行的「查找」只把命中片段标黄、不过滤行，「筛选」只留包含关键字的行并标绿，同一片段同时命中显示橙色，`Esc` 清空；点「复制」把当前框里显示的内容拷到剪贴板，有筛选时只拷筛选后的行）。命中断点 / 单步暂停会自动打开源码面板并定位到当前行（卡片原本关着也会开）；在当前这个暂停点上手动「收起」后不会再自己弹回来，换下一个断点照常打开。整页不滚动，每个面板只在自己框里滚。窗口窄（≤1180px）会退回上下堆叠、窗口矮（≤840px）改由整页滚，两种回退都会给长列表 / 长文件封顶（断点 40vh、变量 40vh、源码 60vh），不会把断点区压成一条缝。

**使用步骤**：

1. 打开 Tab（或 `http://127.0.0.1:<gui 端口>/#debug`）；
2. 起 app：选「项目目录」（候选 = 已连接会话反推的项目根 + 最近用过的目录，与 AI 调试页同一份配置）、「设备」（默认本机桌面）、「入口」（可空，默认 `lib/main.dart`），点「启动 / 复用」；**同设备同目录已有本工具拉起的会话时直接复用**（状态行会写「复用」，不重装包）。已在跑的会话也可以从「接入会话」下拉选一条点「接入」：本工具（GUI / MCP）拉起的会话会按 VM 端口认领到句柄，热重载/热重启/停止都能用；外部 IDE / 终端起的会话也能接，断点、暂停、单步、栈与变量全可用，但热重载/热重启/停止不可用（那几个要进程句柄）；
3. 打断点：点断点卡片右上的「源码下断点」打开源码面板——优先按**当前调试会话的项目根**（没连会话时用「项目目录」，两者不一致会自动把目录框同步过来），列出项目内 `.dart` 并打开 `lib/main.dart`（输入框支持全路径 / 部分路径 / 只给文件名过滤，回车打开）；**点行号就是下断点，再点一次取消**，已下的行标 `●`、暂停命中的当前行为整行浅黄 + 左侧金条（IDE 的「跟随当前帧」）：点「↷ 跳过 / ↘ 进入 / ↖ 跳出」后当前行跟着栈顶帧往下走，同文件自动滚动、换文件自动切换；单步进入 Flutter SDK / 依赖包时也会切过去只读展示（见下方边界）；顶部「条件」（如 `i > 5`）和「日志表达式」（如 `i=$i`）填了再点行号，下出来就是条件 / 日志断点。也可以照旧手输 `文件:行`（相对项目根，如 `lib/main.dart:87`），点「加断点」。断点表里可启用/禁用、删除（标题行的「停用全部 / 启用全部」可一键切换，断点不删只切启停，没断点时按钮是灰的），点 `✎` 可**就地改**条件 / 日志表达式（位置置只读，换位置请删除重加；「保存修改」不重下发 VM 断点，id 与启停状态不变）；条件不满足时自动继续，输出区留一行「条件未命中」；填了日志表达式就是**日志断点**——命中不暂停，输出区留一行 `[logpoint] 文件:行  i=$i => i=3` 后自动继续（表达式先按 Dart 求值，不合法再按字符串插值重试；求值失败只写原因，不影响 app 继续跑）。断点会自动记住（下方「已记住」清单，按项目根存 `$XB_UME_HOME/debug/breakpoints.json`，含条件、日志表达式与停用状态）：GUI 重启、断开再接入、重跑同一个项目时自动重下并提示「已恢复 N 个记住的断点」；点「忘记」清空当前项目，点「全部项目」看所有项目分组的清单（每组 `✕` 单独清空）；日志断点在清单里带 `log` 标记。清单每行末尾的「启用 / 停用」可点（停用态显示「启用」）：没连会话也能改，下次接入按这个状态恢复（停用的恢复后立刻 `setBreakpointState(false)`）；当前会话里正好有同一位置的断点时后端会一并切它的启停，提示里带「（当前会话已同步）」——不会出现「点了停用可断点还在命中」。异常/网络页的源码行还有「断点」链接可一键下断点（未连会话时只记住）。断点卡片里还有一个「**路由栈**」小节（点「刷新」）：列出**当前调试会话**的 Navigator 路由与对应文件（`N1#2 路由名 类型 文件:行`，项目内显示相对路径），点「文件:行」就在下方源码面板打开并定位到该行（再点行号即下断点）；与「路由栈」Tab 用同一套 `routestack` / `routelocate`，没连会话时只提示先接入；每个路由下面还有一行 `Widget / State / VM / Notifier` 类名（同一套 `routeinfo` 静态解析）：**点类名就在下方源码面板打开并定位到该类声明行**（点行号即下断点），名字后的小 `◎` 跳到「实例」Tab 自动查找该类对象；依赖包 / SDK 里找不到源码的类显示为灰字（hover 可看原因）；断点表、这个路由栈小节、已记住清单（含「全部项目」总览）的每行末尾都有「跳转」——用**守护进程 Tab 里排好的 IDE 顺序**（`$XB_UME_HOME/config.json` 的 `ideOrder`）打开该文件并定位到行，与路由栈 Tab / 异常 Tab 的「跳转」同一条通道（`/api/openide`）；找不到可用 IDE 时会把 `路径:行` 复制到剪贴板并提示。路由栈行的「文件:行」本身仍然是开下方源码面板，`跳转` 才唤起 IDE（定位成功后才出现）；落盘清单的 `path` 是相对项目根的，跳转会自动换成绝对路径，不会拿 GUI 进程的当前目录去碰运气；
4. 命中后底部浮动条出现并高亮，左侧显示 `函数 · 文件:行`；中栏的「调用栈 / 变量」同步显示最多 32 帧（点帧切换上下文）、该帧的可见变量（一层，可逐层展开）、变量筛选框与求值输入框；
5. 用浮动条控制：⏸暂停（app 空闲、没有 Dart 帧时栈为空，属正常）、▶继续、↷跳过 / ↘进入 / ↖跳出（单步，源码面板的当前行跟着走）、⟳热重载 / ⥀热重启（热重启后断点按快照自动重下）、■停止（只停本工具拉起的进程，按精确 PID）；
6. 「运行输出」区跟 `flutter run` 日志：复用/接入时先补最近 200 行，之后增量追加，可「跟随」（自动滚到底）与清屏。**启动失败也会把这次日志接到这里**（状态行显示「启动失败：…」，提示只留几秒，真正的原因看输出区末尾）：失败摘要取日志**末尾**，命中 `hdc` 的 `Connect server failed` + `fport`（端口转发失败：装包通常已成功，只是拿不到 VM service）时会附处置建议——先清掉多余的 `hdc` 客户端，或 `hdc kill -r` 重启 hdc server（会断开其它正在跑的 hdc 会话）后再点启动。**起进程前还会给 hdc 做一次体检**（OHOS）：先回收历次部署遗留的孤儿日志客户端（`hdc -t … hilog`，PPID=1；DevEco 的 `shell hilog` 形态不动），再探一次 `hdc list targets`，回收后仍不通就自动 `hdc kill -r` 重启 server；做过的处置写在状态行（如「回收 hdc 遗留日志客户端 3 个」）。

**全局快捷键（热重载 / 热重启，系统级）**：浮动条上「⟳ 热重载」「⥀ 热重启」右侧会显示当前键位（没设置就不显示），旁边的「快捷键」按钮打开设置。打开弹窗：点一下热重载 / 热重启那一行进入「按下组合键…」，按完自动勾上「启用」，再点「保存并应用」（约 1 秒生效）；`Esc` 取消录制、`⌫` 清除该行、行尾「清除」单条清空。规矩：**必须带一个修饰键**（macOS 是 `⌘` / `⌃` / `⌥`，Windows 是 `Ctrl` / `Alt` / `Win`；只按 `⇧` 不算，纯按键会把正常输入吞掉）、两个动作不能是同一组合、字母 / 数字 / `F1`~`F20` / 方向键 / 标点都支持，按到不支持的键会当场提示。弹窗下半部分显示监听器是否在跑（pid）、已注册了哪些键位、注册失败原因（常见是被别的软件占用）、最近一次触发结果与日志路径。`hotkeys.json` 在 macOS / Windows 之间可以直接搬（两张键码表收录的键完全一致）。

为什么说「全局」：热键是**系统级注册**——macOS 用 Carbon `RegisterEventHotKey`（**不需要辅助功能授权**），Windows 用 user32 `RegisterHotKey`（主 isolate 阻塞在 `GetMessage` 消息泵上取 `WM_HOTKEY`，带 `MOD_NOREPEAT` 所以长按不会连发）；两边都由 GUI 拉起的独立子进程 `src/hotkeys/hotkey_listener.dart` 注册，按下时回调 GUI 的 `/api/hotkey/action` 再由调试中枢触发重载：macOS 对会话进程发 `SIGUSR1` / `SIGUSR2`（Windows 没有这两个信号，改为写本工具拉起会话的 stdin `r` / `R`——所以 **Windows 上只能用在本工具拉起的 `flutter run` 上**，IDE / 终端起的会话拿不到句柄，会提示只读）。所以**工具箱页面关掉、当前停在别的软件里都照常生效**——页面只是设置入口，不用担心切窗口失灵。配置落 `$XB_UME_HOME/hotkeys.json`（可手工编辑，改完在弹窗点「保存并应用」或重启工具箱）；状态 `hotkeys.status.json`、日志 `hotkeys.log`。GUI 退出会一起收掉监听器（Windows 用 `tasklist` / `Get-CimInstance` 按 pid 复核命令行，不按名字模糊杀）；如果 GUI 被强杀，监听器 60 秒（12 次心跳）等不到 GUI 会自己退出，不会留孤儿占着你的热键。快捷键通常在没打开调试页时按，所以拿不到「当前会话」时会自动认领**本工具唯一拉起的那个 `flutter run`**；同时有几个会话就只提示、让你在调试页选定后再按，不会猜着热重载错的那个。

**完成后发系统通知 + 提示音（默认开）**：不管热重载 / 热重启是点浮动条还是按全局热键触发的，只要跑成功就弹一条系统级通知并响一声——macOS 进通知中心（Glass 提示音），Windows 是托盘气泡（系统音）；标题「热重载完成」/「热重启完成」，正文就是那句结果（用时、编译输出，「已暂停在断点」也会带上）。它解决的就是「按完热键眼睛还在 IDE 里」：页内提示看不到，系统通知不管你前台是哪个软件。**为什么还要响一声**：实测开专注 / 勿扰、或者「脚本编辑器」没授权通知时，macOS 会把 `display notification` 静默吞掉（日志里有 Presenting、屏幕上什么都没有），而普通音频播放不受这个限制，两层至少保一层能感知。开关在同一个「快捷键」弹窗里，与是否启用热键**无关**——不开热键、只用按钮也能收；关掉只影响通知与声音，浮动条与页面提示照旧。

**变量筛选**：变量区上方的输入框按**名字包含**筛选（忽略大小写），填 `count` 会留下 `_count`、`_notificationCallStackDepth` 这类名字，其余行隐藏；命中片段高亮，通往命中项的祖先行一起保留（箭头给 ▼ 表示下面是命中路径），右侧显示命中条数。**没展开过的层也会被搜到**：输入停下 300ms 后自动把整棵变量树拉下来补扫（BFS，边拉边显示，状态栏「筛选中… 已查 N 个对象」），命中项逐个补出来，不用先手动展开。为免把整个 Element 树搬下来，最多扫 300 个对象 / 8 层，到顶会写「达到扫描上限」——此时更深的层没扫到；想立刻看某个命中节点的下一层，点它前面的 `▶` 就只拉这一层（`▶` 变 `▼`，清空筛选后也是展开态）。改词 / 清空会作废还没跑完的扫描，不会串结果。筛选框右侧的「**我的**」（默认勾上）只保留**声明在你项目包里**的字段：`ChangeNotifier` 的 `_count`（监听器个数）、`_listeners` 这类框架内部字段会按名字一起搜到，但它们不是你的数据，勾上后收起只计数（状态栏「N 条 · 隐藏 M 个框架字段」）；同时扫描也不再往框架对象里钻（`_element` 那棵 Element / RenderObject 树不再吃掉扫描上限）。想看框架 / 依赖库里的字段就取消勾选，会立刻补扫并显示全部。**结果可以折叠**：命中项的祖先行点一下收起这一段（`▼` 变 `▶`），再点展开，右侧命中条数按整棵树计算、收起不变；还没拉过的节点前面的 `▶` 是「点一下拉这一层」，拉过之后才是折叠。`Esc` 或清空输入恢复原树。
**求值报错怎么读**：暂停后在「求值」框里写表达式，报错不再铺一整段 Dart 编译错误，而是压成一句「`DoorLockHomePage` 没有成员 `runTimeType`；试试 `runtimeType`」（完整原文仍在悬停里）：

- 拼写候选来自**本机源码**：按错误里的类名找到类体，扫字段 / getter / 方法名，再按编辑距离取最近的 1~2 个（不分大小写）；`runtimeType` / `widget` / `context` 这类不写在类体里的继承成员另有一份常用成员兜底；
- 写错对象时给完整表达式：在**已展开的变量树**里反查同名字段（`controlFinishLoad` → `refreshController.controlFinishLoad`），只查已加载的层，不会因为报错再发一轮 `getObject`；
- 两种提示都没有（成员名确实不存在、类在依赖包 / SDK 里读不到源码）就只显示「类 X 没有成员 Y」，完整错误在悬停里；
- `_` 开头的私有成员不是写错，而是**读不到**：Dart 的私有名按库区分，求值表达式编译在合成库里，别的库的 `_count` 解析不到。这时提示会直接说明原因，并让你去变量树 / 「实例」Tab 看值，而不是给一个「试试 this.controller._count」式的自指建议（建议与已输入表达式相同时一律丢弃，忽略空白与 `this.` 前缀）；拼写候选会拼回你写的那一行（`controller.controlFinshLoad` → `controller.controlFinishLoad`），提示里的表达式可以直接粘回输入框。

**运行配置（按名字选着跑）**：工具条里多一行「运行配置」——下拉选择 / 新建编辑 / 删除 / 导入 launch.json + 「追加参数」+ 摘要 + 刷新 + 打开配置。数据来自 `$XB_UME_HOME/debug/run_profiles.json`（按项目根绝对路径索引，与断点落盘同目录）。完整字段见 [README](README.md#项目运行配置按名字选着跑)。

- **下拉**：列出这个项目的具名配置（如 `cn debug` / `oversea release`），选中一条再点「启动 / 复用」，入口 / 设备 / 参数 / 环境变量 / 预启动都按该配置来；切换即记住（写 `last`），GUI 重开自动回填上次选择。
- **新建 / 编辑**：弹窗填名称（必填）/ 入口 / 限定平台 / 参数 / 预启动 / 停止后 / env / 备注；同名即覆盖。参数、平台、env 都是文本框，**分词与拆行在后端做**（与启动链路一套规则），`--dart-define="a b"` 这种带引号的写法不会拆坏。
- **删除**：删当前选中的那条；如果它正是 `last` 指向的，`last` 一并清掉。
- **导入 launch.json**：把项目 `.vscode/launch.json`（含 `tasks.json` 的 `preLaunchTask`）转成普通配置（可读懂 JSONC 注释 / 尾逗号；`env` 跟着转，`envFile` 只给提示）；先预览再确认，同名会列出来，导入后运行时不读 launch.json。
- **追加参数**：只对本次启动生效（不写进配置），回车 / 失焦即记住，下次自动带上；例如临时加 `--dart-define=LOG=1`。
- 摘要行显示「N 条配置 + 当前配置」；`preRun` 仍在**新建**会话时执行（复用不重跑），输出写在本次日志头部；`postStop` 在「停止」按精确 PID 杀完进程后执行；配置不存在 / 限定平台与当前设备不符时**当场报错**（列出可用配置名 / 当前平台），不会默默跑错包；复用判定带配置名（同设备同目录同 target 但配置不同 → 不复用）。

**边界**：

- 「停止」不会按名字杀进程，只结束本工具（GUI / MCP）拉起、PID 对得上的那棵进程树；外部 IDE 起的会话请在它自己那边停；
- 服务协议客户端断开时 VM 会删掉它创建的断点，断点表当场就空了——靠「已记住」清单在下次 `启动 / 接入` 到**同一项目根**时自动重下；换目录 / 换项目不会串用（清单按项目根分开存：加 / 删 / 启停 / 改 / 忘记都只动自己那组，接入另一个项目的会话也不会沿用上一个会话的项目根）。行号被删或文件改名时该条恢复失败，只计数提示、不删记录（切回分支往往又能用）；
- 源码面板只读：列项目内 `.dart`（跳过 `.dart_tool` / `build` / `.git` 等构建与隐藏目录，最多 2000 个），单文件最多显示 4000 行、单行超 600 字符截断；不做语法高亮、不能编辑。项目内的文件经符号链接解析后必须仍在项目根内；单步进入 Flutter SDK / 依赖包时面板会切到那份源码（按项目 `.dart_tool/package_config.json` 解析 `package:` URI），但它是**只读跟随当前帧**——点行号只提示、不会下断点（框架源码行号随 SDK 版本变，存下来下次恢复只会失败）；
- 条件断点是客户端判定的（VM 的 `addBreakpoint` 没有 `condition` 参数）：每次命中都会真暂停、求值后再自动继续，条件写得越窄越好；日志断点同理（VM 也没有 `logMessage`），每次命中都会真暂停、求值后自动继续，与条件同时填时先判条件、false 时连日志也不打印；
- 鸿蒙 Flutter 引擎没有表达式编译服务，变量面板不受影响，但「求值」会报不支持；断点与单步不受影响。

### 5. 日志查看（Tab「日志」）

**功能**：实时展示「VM 会话 + 设备」组合日志，双数据源合并。

**过滤规则**（由页头右侧的两个下拉框决定）：

| 选择状态 | 展示内容 |
|---|---|
| VM、设备都未选 | **不打印**（提示先在页头右侧选择） |
| 只选 VM | 仅该会话的 Flutter 输出 |
| 只选设备 | 该设备的设备日志 + **属于该设备**的 VM 输出（一台设备可同时跑多个 app，即多个 VM） |
| 同时选 VM + 设备 | 两个源**都打印**（并集）：选中的 VM 输出 + 选中设备的日志，互不约束 |

VM→设备的归属判定（仅「只选设备」时用于筛选 VM 输出）：会话来源带设备号时（如 `adb:SERIAL#port:x`）**精确匹配**；否则按平台推断（getVM 的 operatingSystem 与设备平台比对，如 mac 上的 VM 永远不会归属到手机）。同平台多台设备同时在线时，无设备号的会话无法区分属于哪台（已知局限）。切换选择只改变显示，**不清屏、不中断采集**。

**两个数据源**（可分别开关）：

| 来源 | 内容 | 对应场景 |
|---|---|---|
| 设备日志（logcat / hilog / iOS log） | 各设备的**全量**系统日志：Flutter 输出、native 层、系统组件、三方 SDK——**包含 flutter run 控制台不打印的内容** | 排查 native 崩溃、看被控制台过滤掉的日志 |
| Flutter 输出（stdout/stderr） | 全部调试会话中 app 进程的标准输出/错误流，与 `flutter run` 控制台中 app 输出的部分一致 | 专注看 Flutter 层 `print`/`debugPrint`/异常输出 |

**使用步骤**：

1. 在页头右侧按需选择设备/VM 会话（默认全部）；
2. 电脑上正常 `flutter run` 启动调试，日志开始实时滚动；
3. 用工具栏过滤（按作用对象分成两个组框，作用范围从布局即可看出）：
   - **「设备日志」组**：勾选启用后，组内的级别筛选（V·详细 / D·调试 / I·信息 / W·警告 / E·错误）生效；取消启用时整组置灰不可点；未选设备时组内无日志（设备在页头右侧选择）；
   - **「Flutter 输出」组**：只控制 Flutter 输出的显隐，**不受级别筛选影响**（stderr 错误通道输出标为 E·错误着色）；来源由页头右侧的会话下拉框选择（默认「未选择会话」，未选会话且未选设备时不打印）；悬停组框可看说明；
   - **关键字**：空格分隔多个关键字，日志包含**任一**关键字即显示（对消息和 tag 不区分大小写）；输入防抖 200ms；实时生效——新日志到达时只增量追加命中行，无命中时 DOM 完全不动，**选中文字/复制不会被刷新打断**；新行只在底部追加，往上翻阅时不会被强制拉底，滚回底部后恢复跟随
4. 「到顶」「到底」一键滚动到最早/最新日志（到底后恢复自动跟随新日志；到顶后新日志不会拉走视图）；「复制」把框中当前显示（含过滤）的全部日志逐行复制到剪贴板（直接读渲染行，所见即所得；被「启用」开关隐藏的来源不计入）；「暂停」停止页面滚动（服务端仍在收集，取消暂停后继续渲染新日志）；「清屏」清 空当前显示；「导出」下载当前缓冲的全部日志为 txt（导出与复制的区别：导出走服务端 5000 条环形缓冲含未显示来源，复制只取框中当前显示的行）；
5. 每行格式：`时间 [来源] TAG 消息`，级别着色（E 红 / W 黄 / D 蓝 / I 白 / V 灰）；
6. 服务端与页面各保留最近 5000 行（环形缓冲），更早的自动丢弃以防内存膨胀；缓冲按来源分额——同一会话/设备（source + tag + device）最多占 1000 条，超出先丢自己的旧行；总量超限时优先丢最旧的非 Flutter 行。这样单个高频会话或设备日志洪流不会把其他来源整片挤掉（否则切到安静会话时即使勾选「Flutter 输出」也会空白）。页面侧另有渲染上限：最多保留 4000 行 DOM（超过 4200 才批量裁剪一次，已关闭来源的隐藏行优先丢、当前显示的来源优先保留），更早的行用「导出」查看；「设备日志」/「Flutter 输出」的启用开关只切换已有行的显隐、不重建 DOM，设备日志高频滚动时勾选/取消也不会卡（实测 20 次切换共 2ms）；若切换后对应来源的行此前已被渲染上限裁掉（但缓冲里还有），会按缓冲重建一次补齐。

**注意**：

- 同一份服务端缓冲还开了分页 JSON 接口 `GET /api/logs`（参数 `keyword` / `source` / `sinceMs` / `offset` / `limit` / `tail` / `maxChars`，返回 `items` / `total` / `nextOffset` / `nextSinceMs` / `sources`），MCP 的 `xbume_log_history` 就是它的薄封装——「导出」是一次性拿全量 txt，跟历史用这个分页接口更省上下文；
- 「Flutter 输出」源覆盖**所有**调试会话：多个 Flutter 应用同时接入（无论多台手机还是同一台手机装多个 app）时，每行 tag 列显示会话来源（如 `adb:设备号#port:本机端口`），可用关键字过滤区分不同应用的输出；IDE 跳转各会话独立处理，互不影响；
- 设备日志流在设备断开时自动重连；对应命令行工具（adb/hdc 等）未安装时会提示一次，不会刷屏。

### 6. 统一时间轴（Tab「时间轴」）

**功能**：把**路由、网络、日志、异常、监听**五类调试事件按时间合并成一条流，用来对齐「一次操作前后 app 内先后发生了什么」。

**使用**：

1. 页头右侧选择 VM 会话；切到「时间轴」Tab 自动开始同步（路由/网络每 1.5s 增量拉取，仅本 Tab 激活期间运行，切走即停）；
2. 工具栏过滤：
   - **范围**：最近 1 / 5 / 30 分钟或全部（默认 5 分钟）；
   - **类型**：路由 / 网络 / 日志 / 异常 / 监听五个勾选框，行左侧色条对应（路由绿、网络蓝、日志灰、异常红、监听黄）；
   - **日志级别**：`Flutter I`（只看 Info）/ `W·E`（Warning + Error）/ `D·V`（含 Debug/Verbose），只作用于「日志」类型；
   - **关键字**：空格分隔多个关键字，任一对摘要或详情命中即显示；
3. 行内从左到右：时间（时:分:秒.毫秒）/ 类型徽标 / 摘要 / 右侧状态（网络状态码与耗时、路由 action、异常通道、日志来源）；**点击行展开/收起详情**（可同时展开多条）；
4. 详情内容：
   - 路由：action、目标路由、来源路由、phase 与事件 id；行尾「在路由栈中定位该路由」跳到路由栈 Tab、滚动到同名路由行并闪烁高亮（该路由已被 pop、不在当前栈时底部提示）；
   - 网络：方法、URL、状态码、耗时、错误；行尾「在 Network 中查看详情」跳到 Network Tab，自动展开该条并滚动定位、闪烁高亮；
   - 异常：摘要、描述、相关 Widget 位置、栈帧；行尾「在异常 Tab 中定位该条」跳到异常 Tab、滚动到对应异常卡片并闪烁高亮；
   - 监听：监听名与表达式、旧值/新值、条件与是否命中、累计变化/截图次数；条件命中自动截图时直接给出 PNG 链接，字段监听可「在实例 Tab 中定位该监听」；
   - 日志：来源、tag、完整消息；行尾「在日志 Tab 中定位该行」跳到日志 Tab、滚动到该行并闪烁高亮（若日志 Tab 的关键字/来源/级别过滤挡住了目标行，会自动放开过滤保证可见）；
5. 「暂停」冻结当前视图（服务端仍在收集/合并在后台继续），暂停期间底部浮出「有新事件（点击恢复并跳到底部）」浮条，点它自动恢复并滚到最新；「最新」一键滚到底部（暂停中点击会同时恢复）；「复制」把当前显示（含过滤）逐行复制到剪贴板；
6. 「清空」只清空时间轴里的**路由/网络/监听**副本（**不动 app 内记录**，也不影响日志/异常），并以当前时刻为下限，之后的轮询不会把清空前的旧记录再带回来；同一会话切走再切回保留已合并的历史。

**数据来源与时间基准**：

| 类型 | 来源 | 时间基准 |
|---|---|---|
| 路由 | `XBUme.controller.routes`（VM service eval） | app 端事件时间（毫秒） |
| 网络 | `XBUme.controller.network`（VM service eval） | app 端事件时间（毫秒） |
| 日志 | 页面实时接收的设备日志 + 各会话 stdout/stderr | 本机接收时间（毫秒） |
| 异常 | 页面实时接收的异常流 | 本机捕获时间（毫秒） |
| 监听 | GUI 端 Watch 管理器轮询（VM service evaluate） | 本机采样时间（毫秒） |

同一毫秒的排序权重：异常 > 网络 > 监听 = 路由 > 日志。手机与本机时钟偏差较大时，路由/网络与日志/异常的相对顺序可能偏移（本机同机调试无此问题）。

**说明**：仅 debug 会话可用；日志/异常与「日志」「异常」Tab 共用同一份前端缓存，页头设备/会话过滤变化会同步反映到时间轴；app 未接入 xb_ume 时路由/网络为空，日志/异常不受影响。

## 四、应用沙盒（Tab「应用沙盒」）

**前提**：在页头右侧选中某个 VM 会话后，本 Tab 才展示内容；未选择时显示「请先选择 VM」。

**原理**：通过 VM service 的 evaluate 在 **app 进程内**执行 dart:io 代码读写文件系统，零 app 端改动，适用于任何 debug 模式的 Flutter 应用（release 无 VM service，不可用）。

**使用**：

1. 页头右侧选中调试会话后，Tab 内自动定位 app 的可访问根目录（多入口自动探测：HOME、系统临时目录、平台约定沙盒路径——鸿蒙为 `/data/storage/el2/base`、`/data/storage/el1/base`，Android 会在 app 内读 `/proc/self/cmdline` 取包名并优先探测 `/data/data/<包名>`、`/data/user/0/<包名>`、`/storage/emulated/0/Android/data/<包名>/files` 等本应用沙盒，取可成功列目录的作为入口）；HOME 不可访问时（如鸿蒙真机）自动回退到沙盒映射路径，多个入口时顶部显示「入口」快捷链接；
2. 点目录名逐层进入，点面包屑逐级返回；列表显示名称/大小/修改时间，`[链接]` 标记的是符号链接（不可进入，下载时按文件尝试）；访问受限的目录会提示「无权限访问」并列出可尝试的其他入口；
3. 文件点「下载」保存原文件；目录点「下载 .tar」递归打包（USTAR 无压缩）下载；
4. **上传**：每行都有「上传」链接——目录行把本地文件写入该目录，文件行写入其所在目录。选择本地文件后经 base64 编码上传、app 内 eval 分块写入（同名覆盖、深层目录自动创建，单个文件上限 12MB），完成后自动刷新列表；文件名禁止含路径分隔符或 `..`（防目录穿越）；
5. 点行尾「删除」移除文件或文件夹（**文件夹递归删除全部内容**）。删除是敏感操作：点击后弹出确认框（显示类型、名称与完整路径），确认后才执行，且**不可恢复**；删除成功后自动刷新当前目录。后端会拒绝删除文件系统根等不合法路径；
6. 文件行点「查看」「监听」会在浏览器**新标签页**打开独立页面（不影响主页面浏览），两页均支持搜索与过滤（可同时使用，先过滤再在筛出的行内高亮搜索，**过滤命中的关键字同样会高亮**）：
   - **查看**：分块流式读取并展示文件当前全部内容（静态快照，**不限文件大小**，读取中显示进度）；搜索高亮全部匹配处并显示匹配总数，过滤只保留匹配行；
   - **监听**：GUI 版 `tail -f`——从文件末尾开始，每 2 秒轮询增量并追加显示（文件轮转/重建会提示，可点「重新开始」；支持「暂停/继续」）；搜索高亮新增内容，过滤只保留匹配行；**内存保护：最多保留最近 5 万行**，超限丢弃最早行并在状态栏提示累计丢弃量（完整内容用「查看」页或「下载」本地看）；
   - 分段读取已按 UTF-8 边界切割，多字节字符（中文等）不会被切断出现乱码。

**说明**：文件/文件夹下载**无大小限制**——分段流式传输（每次 1MB + gzip 压缩经 VM service 中转），app 与本机内存占用恒定；大文件下载耗时随体积线性增长（实测约 2MB/s，30MB 文件约 15 秒）；tar 不保留空目录。

**注意**：可浏览范围是 app 进程可见的全部路径，请勿在不可信环境开启本功能。

## 五、数据库（Tab「数据库」）

**用途**：在电脑上直接浏览调试会话 app 沙盒里的 SQLite 数据库（`.db` / `.sqlite` / `.sqlite3` / `.db3`），查看表结构与数据、分页浏览、执行只读 SQL、导出 CSV，**app 端零改动**。

**入口**：在 Tab「应用沙盒」里找到数据库文件，点行首的「查询」按钮——会自动切到「数据库」Tab 并打开该库。

**原理**：打开时通过 VM service 分块（每次 1MB + gzip）把库文件拉到本机缓存 `~/.xb_ume_ide/db/<8位哈希>.db`（缓存键 = 会话 uri + 文件路径 + 大小 + 修改时间，命中则直接复用、不重复拉取），再用**本机 `sqlite3` 命令行以 `-readonly` 只读模式**执行查询。因此：

- 依赖本机安装 `sqlite3`（macOS 自带；Windows / Linux 需安装并加入 PATH）；
- 浏览的是**拉取那一刻的快照**，app 之后写入的新数据需要点「重新拉取」才能看到；
- 写操作（DELETE / UPDATE / INSERT / DDL）全部被拒绝，不会影响 app 内的真实数据；
- 单个库文件上限 256MB（超出请先下载到本机用其他工具打开）。

**功能**：

1. **表 / 视图**：左栏列出全部表与视图（`sqlite_` 内部表除外），点击切换；打开库时默认自动展示第一张表；
2. **结构**：显示选中表的列（名称/类型/非空/主键/默认值）、索引与建表 SQL（默认折叠）；
3. **数据浏览**：点表自动执行 `SELECT * FROM "表" LIMIT 100 OFFSET 0`，底部分页「上一页 / 下一页」每页 100 行，并显示当前行区间；
4. **执行 SQL**：顶部输入框可写任意单条只读 SQL（**一次只能一条**，去掉结尾分号后不允许再出现分号，长度上限 20000 字符），回车或点「执行」；状态栏显示行数与耗时。手写 SQL 的结果不分页（翻页按钮隐藏），需要分页请在 SQL 里自己写 LIMIT/OFFSET；
5. **导出 CSV**：对当前 SQL 结果导出 CSV——UTF-8 带 BOM（Excel 打开中文不乱码）、字段按 RFC 4180 转义（逗号/引号/换行）、NULL 导出为空，文件名取原库名（`demo.db` → `demo.csv`）；
6. **重新拉取 / 关闭**：「重新拉取」强制从 app 重新拉取库文件（app 写入后刷新数据用）；「关闭」删除本机缓存文件并清空页面。

**限制**：只读、单条 SQL、快照数据、依赖本机 sqlite3；单次查询 20 秒超时，结果超过 16MB 会被截断并提示加 LIMIT 缩小范围。本 Tab 与其他依赖 VM `evaluate` 的功能一样，要求会话引擎提供表达式编译服务——鸿蒙 Flutter 引擎（无编译服务）与 release/AOT 会话（无 VM service）不可用。

## 六、路由栈（Tab「路由栈」）

**前提**：在页头右侧选中某个 VM 会话后，本 Tab 才展示内容；未选择时显示「请先选择 VM」。

**展示内容**：app 内所有 Navigator 的路由栈，按栈底 → 栈顶排列；每条显示：

- **栈序**（含「栈底」「栈顶」标注）；
- **路由名**（`settings.name`；匿名 push 的页面显示 `<unnamed>`）；
- **类型**（MaterialPageRoute / DialogRoute / BottomSheet 等，弹窗也是路由栈的一层）；
- **参数**（`settings.arguments` 的摘要，悬停看完整内容；复杂对象只显示 toString/类型）；
- **文件**（该页面对应的源码文件名：类声明行，如 `device_advanced_config_page.dart:15`，悬停看完整路径与类名；无法解析时显示 `—`）；
- **Widget / State / VM / Notifier**（页面 Widget 类名 / 其 State 类名 / XBVM 子类名 / 其它 ChangeNotifier 类名，无则显示 `\`；**State 有多个 CN 字段、页面用 Provider `Consumer2/3/4<...>` 监听的多个 CN、以及 `extends XBPage<HomeVM>` 泛型或 `generateVM` 返回类型声明的 VM 都会被识别**——泛型参数逐个验证是否 XBVM / CN 子类）；**点击名称会跳到「实例」Tab 并自动查找该类的实例**（复用实例 Tab 的 Element 树 + 堆扫描双通道查找）；
- **定位**（行尾「跳转」链接，见下文）；
- **操作**（行尾「pop」/「remove」链接，见下文「路由操作」）；
- 栈顶当前路由带 **● 当前** 高亮标记。

嵌套 Navigator（如底部导航每个 Tab 内的 Navigator）分组展示为 Navigator #1、#2… 。

**跳转到源码**：点击行尾「跳转」会用配置的 IDE 打开「文件」列对应的源码文件（定位到页面 Widget 类声明行，不到具体行列）。实现原理：收集该路由子树内的 widget（浅→深）→ 逐个查其类的定义库 → 跳过 Flutter 框架内置类，取第一个能解析到本机源文件的用户类 → 按 `ideOrder` 优先级唤起 IDE（与守护进程的 IDE 跳转同一份 `~/.xb_ume_ide/config.json` 配置）。项目根从调试会话的库路径自动推导，包依赖经项目的 `.dart_tool/package_config.json` 解析；依赖包源码不在本机或整条路由都是框架组件时会提示失败原因。IDE 一个都没找到时会把路径复制到剪贴板兑底。

**刷新方式**：切换到本 Tab 自动拉取一次；也可点「刷新」手动拉取（导航、开关弹窗后点刷新即可看到最新栈）。

**Widget / State / VM / Notifier 列原理**：纯静态解析、零 VM 调用——复用「跳转」已定位 到的用户 widget 类源文件：State 名取 `createState()` 的返回类型；VM 名取 widget 声明处泛型实参（`extends XBPage<HomeVM>`）、`generateVM` 的返回类型或构造调用、State 字段类型、`vmOf/vmWatch/Provider.of/Consumer` 等泛型实参，沿 `extends` 链验证是否 `XBVM` / `XBPageVM` 体系；其余能到 `ChangeNotifier` 的类型归入 Notifier（均仅搜本机项目 `lib/`，框架类型与外部包类型自然跳过）。解析在浏览器加载后自动进行，无需点击。

**原理**：通过 VM service 在 app 进程内（`navigator.dart` 库上下文）读取 NavigatorState 的路由历史，零 app 端改动；仅 debug 模式可用。

**会话限制**：本 Tab 以及实例 Tab 字段读取、Watch 监听、沙盒文件等所有依赖 VM `evaluate` 的功能，都要求会话引擎提供表达式编译服务。鸿蒙 Flutter 引擎（`ohos_arm64`）实测不提供该服务，连 `1 + 1` 也会返回 `Expression compilation error`，此时页面会提示「该调试会话不支持表达式求值（VM 未提供编译服务，常见于鸿蒙 Flutter 引擎）」，换 Android / iOS / macOS 桌面会话即可正常使用；release/AOT 模式没有 VM service，同样不可用。

### 路由操作（pop / remove / pushNamed）

每个 Navigator 分组头部有 **pushNamed 输入框**：输入路由名回车或点按钮，会在 app 内经 `Navigator.pushNamed` 压入该名字的路由。实现上先经 `_routeNamed` 校验：名字解析不出立即报 `UNKNOWN`（名字未注册或该 Navigator 未配置 routes/onGenerateRoute）；部分路由框架（如 Get）对未知名字是抛错而非返回 null，此时提示 `app 内执行报错（FlutterError）`。

行尾「操作」列：

- **pop**：仅栈顶且非唯一路由时可用，走转场动画（与用户手势返回一致）；
- **remove**：任意非唯一路由可用，无转场直接出栈（`Navigator.removeRoute`），适合清理中间残留路由（如反复 push 后忘记退出的测试页）。

操作成功后表格自动刷新（双次延迟，避免拉到出栈前的旧栈）；失败时链接变 ✗，悬停看原因（如「仅栈顶路由可 pop」「栈里只剩一条路由，不能移除」——唯一路由受保护，避免整窗白屏）。

**macOS 桌面会话注意**：app 窗口切到后台（最小化/被遮挡到 hidden）后 Flutter 会暂停帧调度，未完成的转场会冻结在过渡态，此时 pop/remove 虽返回成功但出栈要等窗口回前台、转场完成后才真正生效，路由栈也会显示卡在过渡态的路由。把 app 窗口带回前台即可恢复；真机/模拟器会话无此问题。

### 泄漏检测

工具栏的**「泄漏检测」按钮**：对本会话浏览过的页面 State 类（Widget/State 列解析成功过的类会自动累积，路由栈刷新时已退出的页面类也会记入；另可在输入框手动补类名，逗号分隔）做一次**GC 后堆扫描**：先经 VM service 触发 `_collectAllGarbage`，再对每个类分别统计「树上实例数」（Element 树遍历）与「堆上实例数」（getClassList + getInstances），结果分四类：

- ✓ **栈中存活**：GUI 记录的当前栈里有该类（正常）；
- ✓ **树上存活**：树上有实例（同名类被其它活跃页面使用时不误报）；
- ⚠ **疑似泄漏**（红色）：页面已退出路由栈、GC 后堆上仍有实例 —— 通常是静态变量 / 监听器 / 动画 / 全局 key 等持有，可配合「实例」Tab 展开字段树定位引用链；
- ✓ **已释放**：堆上已无实例。

判定要点：页面被上层不透明页面覆盖时其元素会从树上临时卸载（State 仍由 Route 正常持有），此时树上计 0 属正常，不会误报；类名来自静态解析，带泛型的 State（如 `_FooState<T>`）会自动剥掉泛型再去堆里匹配。记录仅存于浏览器内存（刷新页面重置），多扫几轮路由栈可让候选类更全。仅 debug 模式可用。

## 七、Network（Tab「Network」）

**编辑重放与响应 diff**：每条请求详情头部除「复制 cURL」「重发」外，还有「**编辑重放**」——展开编辑表单（URL / 请求头每行 `k: v` / 请求体，均预填原值），改完点「执行重放」由**电脑直接发起**（不经 app，method 固定为原请求方法），响应展示在「重发响应」卡内，并自动与原响应做**逐字段 diff**：JSON 递归对比（对象按字段、数组按下标），●改 / +增 / −删 三种标注 + 差异计数，完全一致时显示绿色「✓ 与原响应完全一致」；原/新响应任一非 JSON 时降级为提示（人工比对两段响应体）。重放后编辑内容保留在表单中，可连续微调多次重放对比。典型用途：改请求参数验证服务端行为、对比接口版本差异、复现边界参数。


展示**选中调试会话 app 内 xb_ume Network 模块捕获的请求**（与手机端 ume 面板同源数据，不是 GUI 自己抓包），需 app 接入 xb_ume 并配置了网络拦截（`XBUmeHttpClient` / `XBUmeDioInterceptor`）。

**使用**：
1. 页头右侧选中调试会话后切到本 Tab 自动拉取；也可点「刷新」重新拉取；
2. 顶部输入框实时过滤（匹配 URL/方法/状态码/错误信息）；工具栏与「共 N 条」、表头会随页面滚动吸顶（长列表翻到后面也能直接改关键字/看列名）；
3. **点击行展开/收起详情**（可同时展开多条，互不影响；展开的行高亮）：**发起位置**、Query、请求头（app 端已对敏感头脱敏，如 `Authorization: ***`）、请求体、响应头、响应体（JSON 自动格式化）、失败时附错误堆栈；
4. 行尾或详情顶部可操作：
   - **复制全部**：把该请求展开详情的全部内容复制为纯文本（概要行含时间/状态码/耗时，加发起位置、Query、请求头、请求体、响应头、响应体、错误堆栈，以及重发响应（如有）；空节省略）；
   - **cURL**：把该请求复制为 curl 命令（含方法/URL/请求头/请求体）到剪贴板；
   - **重发**：在**电脑上**按原方法/URL/请求头/请求体直接发起 HTTP 请求（不经手机），结果附在该条详情下方（状态码/响应头/响应体）；适合排查「换环境/换参数是否还报错」；跨 host 重放时会自动剥离原请求的 `Authorization` / `Cookie` 等凭据头，避免把原环境令牌发到新地址（在编辑表单里改成新值则保留）；
   - **清空**：清空 app 内 ume 的 Network 记录（与手机端面板的清空等效）；

**请求发起位置**：app 端在请求开始时（`XBUmeNetworkReporter.begin`）捕获调用栈（Dio 场景使用 `RequestOptions.sourceStackTrace`——Dio 5 的 `onRequest` 在独立 Future 中执行，`StackTrace.current` 已丢失用户调用帧），过滤 `dart:` / Flutter / Dio / http / xb_ume / xb_network 等基础设施帧后保留最多 24 个用户代码帧，首帧即发起位置（如 `_requestByDio (package:xb_ume_example/main.dart:152:20)`）。详情顶部「发起位置」展示首帧与可跳转链接，`完整调用栈（N 帧）` 默认折叠；点「跳转」用 GUI 的 IDE 打开对应文件与行（与异常栈帧同一套 `/api/openide`）。旧版 app（xb_ume < 0.3.0）或无该字段的请求显示「未记录」。手机端 ume 面板的 Network 详情同样展示发起位置并提供「跳转发起位置」（走 `xb_ume:openSource` 通道，daemon 负责把 `package:` 解析为本机文件），需 daemon 同为 0.3.0+（重新安装守护脚本）。

**原理**：通过 VM service 在 `package:xb_ume` core 库上下文读 `XBUme.controller.network`（同步 getter，零 app 端改动）；仅 debug 模式可用，app 未接入 xb_ume 时会提示错误。

## 八、Storage（Tab「Storage」）

读写 app 的 **shared_preferences 数据**——Android 为 `/data/data/<包名>/shared_prefs/*.xml`（`<map>` 格式）；鸿蒙为 app 沙盒 preferences 目录（`/data/storage/el2/base/preferences/`，如 `FlutterSharedPreferences`，无扩展名，`<preferences>` 格式）；iOS 为沙盒 `Library/Preferences/<bundleId>.plist`（binary plist，GUI 端经 plutil 转换读写）：列出全部 prefs 文件，展示每个 key 的类型与值，可直接编辑。

**使用**：
1. 顶部下拉选择 prefs 文件，点「刷新」重新读取；
2. 表格中可编辑：值（boolean 用下拉；set 用逗号分隔成员）；已有条目的 **key 与类型不可修改**（key 改名易导致 app 端读写错位，类型由文件解析决定避免类型与值不匹配），仅「新增」行可填写 key 名与选择类型；点行尾「删除」移除该项；点「新增」添加空行；
3. 点「**保存写入（写回手机）**」：按钮先显示「写入中…」（期间禁用，防重复点击）；先按平台格式重建整份文件写回，再把本次改动过的行经 app 内 SharedPreferences API 写回（立即生效）。完成后**无论成功还是失败都会弹窗反馈**：成功为「✓ 已写入并生效（N 项）」/「✓ 已写入并刷新缓存」；需重启或失败为「✓ 已写入文件（需重启 app 生效）」/「✓ 已写入文件（N 项已生效，部分需重启 app）」等并列出具体原因与失败项；弹窗末尾统一附写入的文件名与字节数；
4. 关键字过滤实时匹配 key/value，命中片段**绿色高亮**（过滤生效时 key/值以高亮文本展示，清空过滤后值恢复输入框编辑，key 始终为只读文本）；
5. 「刷新 app 缓存」：让 app 内 SharedPreferences 调 `reload()`（WithCache 用 `reloadCache()`）重读存储。直写文件后想立即读到新值时用；若值与文件仍不一致，说明平台层（Android/鸿蒙/iOS）自己缓存了文件，需重启 app——此时请改用「保存写入」走 API 写回。

**生效时机（重要）**：保存分两步——① 写回存储文件（保证整份内容与页面一致）；② 在 app 内找到 `SharedPreferences` 实例，把改动过的行经 `setString/setBool/setInt/setDouble/setStringList/remove` 写回，插件内存缓存与原生存储一起更新，**保存后立即生效、无需重启 app**（写回后会读回一项校验）。以下情况只写文件、需重启 app：key 没有 `flutter.` 前缀（原生自写 key，经 Dart API 写回会多加前缀）、值类型不支持/非法、app 内没有实例（app 尚未读写过 preferences）；`SharedPreferencesAsync` 本身无缓存，无需刷新。

**原理**：通过 VM service 在 app 进程内读 `/proc/self/cmdline` 取包名（Android）、探测平台对应存储路径并直读/覆写存储文件（零 app 端改动）；Android / 鸿蒙 / iOS debug 会话可用。写文件不把内容拼进 eval 表达式，而是 64KB 分块 `writeAsBytesSync` 到 `<文件>.xbume.tmp` 再 `rename` 原子替换（整份 XML 4MB+ 也不会触发 VM 表达式解析错误，中途失败也不破坏原文件）；保存时按平台格式重建整个文件（Android `<map>` / 鸿蒙 `<preferences>` / iOS plist 经 plutil 转 binary 写回）。iOS 的 plist 复杂类型（dict/date/data）不支持编辑但保存时原样保留；iOS 的 HOME 环境变量为空时用 `Directory.systemTemp` 的父目录（沙盒根）定位 `Library/Preferences`。

## 九、实例（Tab「实例」）

**在 GUI 上直接查看与修改 app 运行时内存里的对象**——比如某个 State 里的 `int age`、Provider 的 ChangeNotifier 里的字段。仅 debug 会话可用。

**上部操作区固定在顶部**：查找行（注册表 Store / 类名 / 查找实例）、Watch 监听区、实例结果列表三者贴顶（整个窗口的滚动发生在这里，字段树再长也不把它们滚走，不用来回滚回顶部）；实例列表与监听列表各自限高内滚（分别 24vh / 18vh），命中多个实例或多条监听时不会把固定区撑满屏幕。

**定位实例的三条途径**：
1. **注册表 Store**：app 端调 `XBUme.registerStore(id, obj)` 注册的对象（如 Provider 的 notifier、全局单例），点「注册表 Store」直接列出；需 app 端 xb_ume 支持该 API（旧版本会提示更新依赖并重启 app）；
2. **Element 树查找**：输入类名点「查找实例」，遍历当前 Widget 树找存活的 State 实例（来源标记「Element 树」）；
3. **堆扫描**：同时用 `getClassList + getInstances` 捞出堆上该类的全部实例（来源标记「堆扫描」），覆盖不在树上的纯逻辑对象；结果去重合并展示。

**字段树**：点行内「查看字段」展开实例字段树——字符串/数字/bool 直接显示值；List/Map 显示条目（上限 100）；嵌套对象递归展开（默认 2 层）；引用可点「展开」继续下 钻；循环引用/已回收实例有明确标注。标题栏有**「仅用户字段」勾选框（默认勾选）**：勾选时隐藏 Flutter/dart SDK 类声明的字段（如 ChangeNotifier 内部的 `_count`/`_listeners`），只看业务字段；取消勾选恢复全部。

**刷新对比**：点字段树标题栏「刷新」重新拉取，**值有变化的字段整行高亮（● + 橙底）并附删除线旧值**（如 `● _count int 42 旧: 1`）；基础值变化、null↔对象、List/Map 长度变化都会标注；点「展开」下钻的深层字段也纳入对比基线；「编辑」保存后的自动刷新会直接显示本次写回的新旧对比。首次打开或切换实例时重新建立基线、不标注。

**编辑写回**：基础类型字段（int/double/bool/String）行尾有「编辑」，输入新值保存即通过 VM service 写回 app 内存（private 字段也可写）；ChangeNotifier 类型的实例写回后会自动 `notifyListeners`（状态栏提示），界面立即刷新。final 字段/不存在字段会返回明确错误。

**原理**：注册表经 VM service 在 `xb_ume_store_registry.dart` 库上下文 eval 读注册 Map；查找走 Element 树遍历 + 堆扫描双通道；字段树用 `getObject` 递归展开；写回是在实例上下文 eval 字段赋值表达式（eval 作用域为实例所属库，私有可见）。

**Watch 监听**：面板顶部的「Watch 监听」区块可对**字段**或 **eval 表达式**设监听，按选定间隔（200ms / 500ms / 1s / 2s，服务端限制在 200ms~10s）轮询取值，**值变化写入时间轴**（类型「监听」，可在时间轴过滤区单独开关）。

- **字段监听**：字段树里 value / ref 行尾的「监听」；只接受标识符形式的字段名，在实例上下文求值（私有字段也可）；
- **表达式监听**：输入表达式后点「监听表达式」，默认在 `package:flutter/src/widgets/binding.dart` 上下文求值；需要访问项目内类时在「库 uri」填该类所在的库（如 `package:xb_ume/src/core/xb_ume_widget_spacing_calculator.dart`）；
- **条件与自动截图**：条件表达式与监听**同上下文**求值，须返回 `bool`（`true` / `false` / `null`）；勾选「条件成立自动截图」后，在 `false → true` 的上升沿截一张图并写入监听事件，PNG 落盘 `~/.xb_ume_ide/scenarios/artifacts/watch-<时间戳>-<序号>.png`，时间轴详情里可直接打开；
- **管理**：列表实时显示当前值、累计变化/截图次数与最近错误，可暂停/恢复/删除；同一目标重复添加会直接返回已有监听（不重复轮询）；连续失败 30 次（表达式写错、实例被回收、会话断开等）自动暂停并在状态里注明；
- **生命周期**：监听由 GUI 服务端常驻轮询（切 Tab / 关页面不中断），删除监听或退出 GUI 后停止；会话短暂断开时下一轮自动重建连接，连续 30 次失败（实例被回收、表达式异常等）自动暂停。

**ChangeNotifier 状态聚合视图**——一屏看清 app 内活跃的 ChangeNotifier（控制器/状态对象）：实例数、监听者数、字段摘要。仅 debug 会话可用。

**使用**：切到「状态」Tab 自动扫描，或在输入框手动补充类名（逗号分隔）后回车。表格列：

| 列 | 含义 |
|---|---|
| CN 类 | 类名，点击跳「实例」Tab 自动查找该类实例 |

## 十一、Widget 树浏览（Tab「Widget树」）

**前提**：页头选中 VM 会话；仅 debug 模式可用。

**布局**：左树右图——左侧 Element 树，右侧 app 实时截图叠加高亮框。

**使用**：

1. 点「刷新树 + 截图」：一次 eval 拉全 Element 树（含每个节点的屏幕 bounds）并抓取当前截图；树默认展开到第 6 层，更深层级点 ▸ 展开；

## 十二、截图遥控与录制（Tab「截图」）

**前提**：页头选中 VM 会话；仅 debug 模式可用。截图来自 `_flutter.screenshot`，坐标按图片物理像素映射，服务端再除以 app 的 devicePixelRatio 转逻辑像素。

**复制图片**：工具栏「复制图片」把当前显示的画面复制到系统剪贴板（不会重新截图）；需要浏览器支持 Clipboard API，失败时提示改用「下载 PNG」。

**遥控**：勾选工具栏「遥控」后生效（开始录制会自动勾选）：

- **单击截图 = Tap**：按下/抬起位移小于 8 物理像素视为点击；
- **按住拖拽 = Swipe**：按下到抬起的位移作为起止点，时长取实际拖拽时间（120–1500ms），拖拽过程中截图区显示黄色轨迹；
- **输入框回车 = Input**：先 tap 目标输入框建立 TextInput 连接，再在输入框输入文本并回车（或点「发送」）；发送空文本可清空当前输入框；
- 操作按顺序串行注入（避免 pointer 事件交叉），成功后 350ms 自动刷新截图；自动刷新与拖拽互斥，避免拖动中被换图；刷新失败时保留上一次画面并提示。

**录制**：点「● 开始录制」，之后每次成功的 Tap/Swipe/Input 自动追加一条步骤（`phys:true`）。两次操作间隔超过 0.9s 会插入一步 `wait`（最长 4s），回放时能等页面/请求完成；input 前的间隔是人工打字时间，不插 wait。步骤可逐条删除、「撤销上一步」或「清空步骤」。

**保存/载入/回放**：

1. 填场景名 →「保存场景」，写入 `~/.xb_ume_ide/scenarios/<名字>.json`（与「自动化」Tab 同一目录，可互相载入/运行）；
2. 下拉「已保存场景」→「载入」，把步骤读回录制区继续编辑或回放；
3. 「▶ 回放当前步骤」复用 `/api/auto/run`：默认失败即停，逐步显示状态、耗时与错误，失败步骤自动落盘截图；结束后可用「在自动化 Tab 查看完整报告」看完整表格；
4. 「■ 停止」在当前步骤结束后停止，剩余步骤标为 skip。

**说明**：遥控端点 `POST /api/remote/op` 只放行 `tap/swipe/input`（不允许 eval/navigate 等通用步骤），单次输入上限 5000 字；它不占用场景执行状态，回放仍由 `/api/auto/run` 串行执行。input 文本会按原文写入场景 JSON，含密码等敏感信息时请注意。macOS 桌面 app 被浏览器完全遮挡时系统可能冻结帧调度，截图会停在最后一帧；录制/回放时把 app 窗口露出来（左右分屏即可）。示例 app 首页的「Login Demo」可用于验收：录制「点 Login Demo → 点账号 → 输入 → 点密码 → 输入 → 点登录」，保存后回放应得到「登录成功：<账号>」。

## 十三、性能监控（Tab「性能」）

**前提**：页头选中 VM 会话；仅 debug 模式可用。页面只监控**当前选中会话**，切换会话会自动清空曲线并从新会话重新采集；离开本页或点「暂停」停止采集，避免持续占用调试通道。

**指标与来源**：

- **CPU（整进程，优先）**：app 端 xb_ume 注册服务扩展 `ext.xbume.processStats`：iOS/macOS 用 `getrusage(RUSAGE_SELF)`、Android/OHOS 读 `/proc/self/stat`，取进程（含 UI、光栅、IO、平台等全部线程）累计 user+sys CPU 时间 ÷ 两次采集的墙钟增量。百分比口径随官方工具切换：iOS/macOS 按 Xcode 调试导航器（单核满载 100%，多核可超 100%，标题「Xcode 口径」）；Android 按 Android Studio CPU Profiler、OHOS 按 DevEco Profiler（以**全部核心容量合计**为 100%，标题「Android Studio 口径 / DevEco 口径」，副标题标出核数，如 8 核下单线程满载约 12.5%）。卡片副标题同时保留本次窗口与 Dart isolate 值，便于交叉验证；旧版 SDK（未注册扩展）或 release 构建自动回退到下面的 isolate 采样，标题会相应变化。
- **CPU（Dart 主 isolate，回退）**：调用 VM service `getCpuSamples`，在近 N 秒窗口内按「忙时样本数 × 采样周期 ÷ 窗口时长」估算，Idle 样本不计入（`GC New` / `GC Old` 标签单独计入 GC 样本数）；只反映 Dart 主 isolate，不含 raster/IO 线程，适合判断业务代码是否把 UI 线程跑满。部分平台的 `flutter run` 启动引擎时没开采样器（实测 OHOS 走 `aa start` 不带引擎参数，`getCpuSamples` 报 `Profiler is disabled`），debug 构建下本页会自动执行 `setFlag('profiler', true)` 后重试（首次采集自动生效，卡片副标题短暂显示「已开启采样」）；product 构建无法运行时开启，会提示不可用。
- **Dart 堆内存**：`getMemoryUsage` 的 `heapUsage` / `heapCapacity`，卡片副标题同时显示堆占用率与堆外内存（`externalUsage`）。
- **进程内存（官方口径）**：Android/OHOS 取 `/proc/self/smaps` 的 PSS（共享页按进程数分摊），与 Android Studio Memory Profiler 的 Total、DevEco Memory 泳道的 PSS 同源；构成表按官方分类拆分——Android 用 `dumpsys meminfo` 的 App Summary 口径（Java / Native / Code / Stack / Graphics / Private Other / System，按私有页公式计算、System 为 PSS 扣除私有页的余量，各行之和恒等于 PSS 总量），OHOS 用 DevEco 内存类型（Native Heap / ArkTS Heap / Stack / GL·Graph / .so / .ttf / .hap / Dev / AnonPage Other / FilePage Other）。iOS/macOS 主数字取 `proc_pid_rusage` 的 `phys_footprint`（Xcode 内存 gauge 口径），RSS 放在副标题。`/proc` 受限时退回 `smaps_rollup`（只有总量），再不行回退 `getProcessMemoryUsage`（进程总内存与顶层分桶，表格用「其他」补齐差额）；GPU memtrack 显存在 app 内不可读，Android 的 Graphics 仅为 smaps 可见部分、OHOS 总量不含 GL/Graph，数值可能略低于官方工具。
- **峰值**：本次页面会话内 CPU、堆、进程内存的最高值，点「清空」归零。

**操作**：

1. 「每 1/2/5 秒」控制采集间隔（采样窗口取 `min(间隔, 2 秒)`，限制 `getCpuSamples` 单次返回的样本量）；
2. 「刷新」立即采集一次（暂停状态下也可用）；「暂停/继续」控制自动采集；
3. 「清空」只清空曲线与峰值，不修改 app；
4. 「触发 GC」复用 `_collectAllGarbage` 触发 app 主 isolate 全量 GC，随后立即重新采集，可用于观察 GC 后堆回落。

**说明**：CPU 百分比是采样估算值，首次进入或窗口内样本不足时可能偏低；设备侧调试通道繁忙时采集耗时会变长，状态栏会显示本次采集耗时。曲线最多保留 90 个采样点，按采集顺序滚动。

## 十四、自动化路径（Tab「自动化」）

**前提**：页头选中 VM 会话；仅 debug 模式可用。场景存电脑端 `~/.xb_ume_ide/scenarios/*.json`（与 app 零侵入，全部通过 VM service eval 驱动）。

**用途**：把「点这里→输入这个→断言那个」的回归验证步骤存成 JSON 场景一键重放，逐步给 status/耗时/期望 vs 实际/失败截图。

**步骤类型**（JSON 数组，每步一个对象）：

| type | 参数 | 说明 |
|---|---|---|
| tap | x, y, phys? | 注入 PointerDown/Up；`phys:true` 为截图物理像素坐标，否则逻辑像素 |
| input | text | 向当前焦点输入框注入文本（需先 tap 输入框建立 TextInputConnection，否则报「无焦点输入框」） |
| swipe | x1,y1,x2,y2, ms?, phys? | 8 段插值 move 模拟拖动/滚动（move 事件带递增 timeStamp 与显式 delta，真实触摸语义，慢拖/fling 均可触发滚动） |
| wait | ms | 等待 |
| back | — | pop 栈顶路由（已是最后一个路由则报错） |
| navigate | name | pushNamed（app 未配命名路由表会报 NO_ROUTE_TABLE/UNKNOWN） |
| assertVisible | widget | 树中存在该类型（支持泛型前缀）且 RenderBox 有尺寸 |
| assertRoute | name | 栈顶路由名包含 name |
| assertInstance | class | 堆/树上存在该类实例（GC 后计数） |
| assertText | contains 或 notContains | 全树页面文本（Text/输入框内容，跳过 Offstage）包含/不包含指定文本 |
| assertRequest | urlContains, method?, not?, withinLastMs? | 最近网络请求中有/无匹配记录（时间窗默认 AI 运行起点，回放场景近 5 分钟） |
| assertLog | contains 或 notContains, level?, source?, withinLastMs? | 最近日志（flutter + 设备 logcat/hilog）中存在/不存在匹配行 |
| eval | expr, expect? | 任意 eval 表达式（binding.dart 上下文），结果含 expect 则过 |

**使用**：

1. 场景下拉选已有场景（或直接在 textarea 写步骤 JSON）→ 填「场景名」→「保存」；「格式化」美化 JSON，「删除」删场景；
2. 「▶ 运行」在选中会话上串行执行；默认失败即停（失败步骤截图落盘），勾「失败继续」跑完所有步骤；执行中「■ 停止」在当前步骤结束后跳过余下；
3. 报告表实时刷新：步骤号/类型/状态（绿 pass / 红 fail / 灰 skip）/耗时/期望/实际/失败截图链接；

**说明**：所有注入都走 `GestureBinding.handlePointerEvent` / `TextInput._instance` eval（零 app 侵入）；macOS 桌面 app 长时间后台后帧调度会冻结（push 动画不完成、新页面元素不上树），跑场景前把 app 置前台；步间默认等 700ms（步骤可加 `waitAfter` 覆盖）让 UI 渲染稳定。

### AI 驱动（自动化页底部区块）

**用途**：不想手写 JSON 时，直接用一句自然语言描述目标（如「打开 XBDialogInputDemo 页面再返回首页」），GUI 自动循环：截图 → 把截图 + 目标 + 历史发给 AI → AI 返回操作指令 → 执行 → 再截图看结果 → 直到 AI 判定完成。适合让 AI 探路；跑通后可一键存为场景 JSON，之后不依赖 AI 直接回放。

**配置（「AI 设置」）**：任意 OpenAI 兼容接口（`/chat/completions`，需支持图片输入）——接口地址（填到 `/v1`，如 `https://api.openai.com/v1`）、密钥、支持视觉的模型名（如 `gpt-4o`、`qwen-vl-max`）。配置存 `~/.xb_ume_ide/ai_config.json`，密钥界面打码显示、保存时不覆盖未修改的打码值。

**使用**：页头选中会话 → 输入目标 →「▶ AI 执行」。每轮显示卡片：轮前截图缩略图（点击看大图）/ AI 分析文本 / 步骤执行表（同场景回放样式）。AI 坐标按截图像素自动换算；某步失败时失败截图会反馈给 AI 下一轮修正；执行中「■ 停止」在当前步骤结束后生效；每轮最多 5 步，轮数无上限（AI 判定完成或手动停止结束），跑之前留意 token 消耗。结束后「存为场景」把本次实际执行的步骤拍平保存，可回上方场景回放。

**测试报告**：运行结束（完成/异常终止/手动停止）后自动生成一份自包含 HTML 测试报告（截图 base64 内嵌，单文件可直接转发），落盘在 `~/.xb_ume_ide/scenarios/reports/ai-<runId>.html`；点结束后出现的「⬇ 导出报告」按钮即可下载（GUI 重启后仍可下载当前运行的那份）。报告含：结论（✅ 目标完成 / ❌ 异常终止 + 原因 / ⚠️ 手动停止）、遇到的问题清单（步骤级失败含期望 vs 实际与失败截图、AI 调用重试轮、轮级错误）、总耗时与步数统计（pass/fail）、逐轮执行明细（AI 思考文本 + 步骤表 + 截图内嵌）。

**AI 总结**：报告顶部（结论之后、问题清单之前）与页面都会显示「AI 总结」，用于回答「这次执行是否满足我给的指令」。结束后把指令原文、运行概况与逐轮记录（think、步骤结果、路由/页面文本/网络/日志证据）发给总结模型，要求逐条拆解指令要求、只依据记录下结论、统计指标先给计数依据再算结果；内容含总体结论、指标表（指标/值/计数依据）、需求覆盖表（你的要求/满足·部分满足·未满足·无法判断/依据）、详细总结、问题与建议、生成信息（模型/耗时/把握度）。指令里的数字要求（如「连续测 20 次」）会做覆盖自检，缺失时自动补一次调用，仍缺失则标注「覆盖可能不全」；指令要求 N 次而实际没跑够时，总结会明确写「仅 N 次、未达标」，不会把未执行次数算成成功或失败。总结只发文本不带截图，最多 3 次调用（含解析失败重试与覆盖补全，退避 2s/4s），单次 45s、总时长 100s 双上限（约 2 分钟）；生成期间进度条显示「正在生成 AI 总结…」并继续轮询，完成后才显示「⬇ 导出报告」。AI 未配置、调用失败或回复不是 JSON 时，报告照常导出，总结区显示「未生成 AI 总结：原因」，原有结论/统计/明细不受影响。另：执行期提示词要求重复/统计类目标在每轮 think 记录「第 k/N 次：成功/失败」，提高事后计数准确度。

**结构化上下文**：除了截图，GUI 每轮还会自动采集四项数据层证据一并发给 AI——当前路由栈 / 页面文本（全树 Text 与输入框内容，去重，跳过 Offstage 保活页面）/ 最近网络请求（本次运行以来，需 app 接入 network 模块）/ 增量日志（上一轮以来的 E/W 级与含 error/exception/fail/crash 关键字的日志，含 flutter 输出与设备 logcat/hilog）。「AI 设置」里可逐项开关（默认全开；关闭后 AI 消息不含该项、对应断言步骤被忽略）。

**说明**：AI 只能返回白名单内的步骤类型（tap/swipe/input/wait/back/assertVisible/assertInstance/assertText/assertRequest/assertLog/eval，eval 提示慎用）；接口请求失败/超时/回复无法解析为 JSON/未给出有效步骤时自动重试（每轮最多重试 3 次，退避 2s/4s/6s，轮卡片显示重试次数），重试期间仍可手动停止；重试耗尽才终止任务并显示原因；AI 接口的可达性取决于你本机网络（内网 网关或公网 API 均可）。

## 十五、多设备并排对比（Tab「对比」）

**用途**：把同一个场景 JSON 在两台设备（两个调试会话）上并行执行，逐步并排展示 状态 / 期望 vs 实际 / 耗时 / 截图，并对运行窗口内的网络请求做两侧差异对照——用来验证「同一功能在不同平台（Android / iOS / macOS / 鸿蒙）表现是否一致」。

**前提**：页头已发现至少 2 个调试会话（仅 debug）；场景来自「自动化」Tab 已保存的场景（对比页只选场景，不直接编辑步骤）。

**使用**：

1. Tab「对比」→ 场景下拉选一个已保存场景（列表与「自动化」Tab 同源）；
2. A / B 各选一个调试会话（同一个会话会被拒绝：`A / B 不能是同一个会话`）；
3. 勾选项：「每步截图」（默认开，用于左右并排对照）、「失败继续」（默认开）；
4. 「▶ 并排运行」：两侧并行执行同一组步骤，页面每 800ms 轮询刷新；任一侧失败/异常不影响另一侧；执行中「■ 停止」在当前步骤结束后对两侧同时生效，余下步骤标 skip；
5. 结果：顶部汇总（A/B 各自 pass/fail 数与步骤耗时之和、不一致步数、总用时）；每个步骤一张卡片，左右两列为 A/B 的状态、耗时、期望、实际、错误与截图（点击看原图）；有差异的步骤行尾标「差异：状态 / 实际值 / 错误 / 耗时（差值 ≥ 200ms）」，勾「只看差异」只显示这些步骤；
6. 页面底部「网络请求对比」：取两侧会话在运行窗口（开始/结束各放宽 2 秒）内的网络请求，按「方法 + URL」聚合，逐行给出两侧次数 / 状态码 / 总耗时，并标「仅 A 有 / 仅 B 有 / 一致」（需 app 接入 Network 模块，未接入时显示「两侧都没有网络请求」）。

**截图说明**：优先用 `_flutter.screenshot`；iOS 等平台该扩展返回 `Could not capture image screenshot.` 时自动退回 `ext.flutter.inspector.screenshot`——对 inspector 根渲染对象 `toImage`（纯 Dart 渲染路径，原分辨率，不含系统状态栏），因此 iOS 模拟器/真机也能拿到对比截图（每步约多 0.5~1s）。

**产物与限制**：截图落在 `~/.xb_ume_ide/scenarios/artifacts/cmp-<时间戳>-{a,b}-step<N>.png`，与「自动化」共用 artifact 下载接口；同一时间只允许一个场景或对比任务在跑（已有任务时返回 409）；两侧会话互不干扰（各自独立的步骤结果与错误）；鸿蒙 Flutter 会话不支持 eval 类步骤。

## 十六、异常（Tab「异常」）

**实时捕获调试会话的异常，App 零接入**：debug 模式下 Flutter 框架自动把异常经 VM service Extension 流上报（`Flutter.Error` 结构化事件，无需 app 做任何事）；GUI 同时解析会话输出流中的未捕获异常块（引擎 `Unhandled Exception:` 与 xb_scaffold `XBErrorHandler catch error:` 两种格式）。10 秒窗口内连续相同的异常自动合并计数（×N）。

**使用**：

1. 切到本 Tab 自动拉取历史异常，之后新异常实时推送（无需手动刷新）；
2. 每条异常卡片展示：时间 / 通道标签（红「框架」/ 橙「未捕获」）/ 来源会话与应用包名 / 合并计数（×N）/ 摘要 / 描述 / 相关 Widget / 栈帧列表；卡片头部行尾「复制」可一键复制本条异常全部内容（头部/摘要/描述/Widget 含文件:行/栈帔逐行，缺省字段自动跳过）；
3. **跳转 IDE**：栈帧中用户代码帧（`package:` 的非 Flutter/dart 帧）行尾有「跳转」，点击按 IDE 优先级（与守护进程同一份 `ideOrder` 配置）打开对应源码行；相关 Widget 的源码位置同样可跳；Flutter/dart 框架帧与无位置帧（如 eval 生成代码）不可跳；
   **一键下断点**：同一行尾另有「断点」——当前调试页已连同一会话时直接在该行下断点（提示「已下断点 文件:行」）；没连会话时写入「已记住」清单，下次在调试页启动/接入同一项目自动生效；位置来自另一条会话（端口不同）时只把位置填到调试页，不会默默下到错的会话上。网络 Tab 的「发起位置」栈帧同样有「断点」；
4. 顶部工具栏：「刷新」重拉全部、「清空」清空列表、「关键字过滤」对摘要/描述/Widget/栈帧/来源实时过滤；
5. **红浮层**：新异常到达时页面右上角弹出红色浮层（含摘要与计数），点击跳到本 Tab，停留 12 秒自动消失；「异常」Tab 标题上的红色徽标显示当前异常总数（进入本 Tab 自动隐藏）。

**AI 归因**：每张异常卡片头部的「AI 分析」会把本条异常发给已配置的 OpenAI 兼容接口（与「自动化 → AI 设置」共用同一份 `~/.xb_ume_ide/ai_config.json`），输出「结论 / 定位 / 修复建议 / 需要补充」四段中文分析，并在卡片内展示依据（源码片段数、帧数、是否有路由栈、网络条数、日志条数）。发送内容：异常摘要与描述、相关 Widget、调用栈（最多 12 帧）、最多 5 个用户代码文件的目标行前后源码、异常发生时的路由栈与页面文本、异常前 30 秒网络请求、异常前后 15 秒同一会话的 E/W 级或含错误关键字的日志。源码片段只读取本机可解析到的文件；Flutter SDK 帧在存在用户帧时不占名额，全是框架帧时才回退展示框架源码。分析结果只保存在当前页面内存中（切 Tab / 新异常重渲染不丢，刷新页面后需重新分析），可点「复制分析」复制全文；AI 未配置、接口失败或异常记录已被清空时，卡片内显示具体错误。

**原理**：GUI 经 daemon 发现各调试会话后，对每个会话同时订阅 Stdout/Stderr/Extension 三条流——Extension 流的 `Flutter.Error` 事件解析出摘要/描述/Widget 位置/栈帧（完整渲染文本也一并保留）；输出流按行喂给状态机，识别异常头行与栈帧行（最多 120 帧，800ms 无新行结算）。栈帧的 `package:` uri 经项目 `.dart_tool/package_config.json` 解析为本机文件路径。仅 debug 模式可用；多会话异常混排但各自标注来源。

**注意（DDS 死锁防护）**：GUI 退出时会主动关闭各会话的流订阅连接（SIGTERM/Ctrl-C 均已处理）——持有流订阅的连接被硬切断（如 `kill -9`、进程崩溃）会让该会话的 DDS 死锁，此后对所有工具（包括 DevTools）无响应，只能重启 `flutter run` 会话。

## 十七、常见问题

| 现象 | 处理 |
|---|---|
| 浏览器没有自动打开 | 手动访问启动日志中打印的地址（如 `http://127.0.0.1:46129`）；`dart run xb_ume:ide --gui` 是 detached 启动，终端无输出属正常 |
| 双击 `.command` 提示无法打开 | macOS 隐藏目录用 `Cmd+Shift+G` 直达；被拦截时右键 → 打开 |
| 设备列表为空 | 确认对应工具可用：终端能运行 `adb devices` / `hdc list targets`；iOS 真机需 `brew install libimobiledevice`；手机需开启 USB 调试并授权 |
| 守护进程显示未运行 | 执行 `dart run xb_ume:ide --install` 安装并启动（详见 `IDE_JUMP_GUIDE.md`） |
| 日志页没有「设备日志」 | 未选中设备，或选中设备的平台工具不可用；「Flutter 输出」源不依赖设备选择，但需要 daemon 正在运行且有调试会话接入 |
| 跑 `flutter test` 时报 `Unable to connect to flutter_tester process` | daemon 会轮询本机 VM service，可能干扰测试进程握手；跑全量测试前先停 daemon（`pgrep -fl ide.dart` 找到 pid 后 kill） |
| Windows 下启动器窗口一闪而过 | 先用命令 `dart %USERPROFILE%\.xb_ume_ide\ide_gui.dart` 前台启动看报错（常见原因：dart 不在 PATH） |
| 页头选中的 VM 会话过一会儿变回「未选择会话」 | 会话 ws 瞬断（热重载/重连）时页面会保持你的选择，连续约 15s 仍缺失才回退；重连后端口变化时按实例指纹自动找回同一会话，回退后指纹保留、会话回来自动重选。若仍频繁掉选，把 `~/.xb_ume_ide/logs/vm_sel.log` 发给开发者排查（记录每次会话增减、用户选择、指纹找回/回退、页面前后台切换，超 2MB 轮转为 `.1`） |
| Network/Storage/路由栈等 Tab 一直转圈或提示「VM service 响应超时」 | 会话已断开（app 退出或 `flutter run` 停止）；重新选择页头右侧的有效会话即可。另外：用 nohup/后台脚本方式启动 `flutter run` 可能使本机 DDS 无响应（stdin EOF），从真实终端或 IDE 启动调试即可恢复 |
| 重启/被杀 GUI 后某个 `flutter run` 会话对所有客户端无响应（DevTools 也连不上） | GUI 非优雅退出（`kill -9` 或崩溃）时持有流订阅的连接被硬切断，可能触发 DDS 死锁；重启该 `flutter run` 会话即可恢复。新版 GUI 退出时已主动关闭连接规避（`kill -9` 仍无法避免） |

## 十八、命令行执行场景（CLI / CI）

同一份场景 JSON 可以不开 GUI、不开浏览器，直接用命令行执行并产出报告，适合 CI 回归：

```bash
# 场景名（~/.xb_ume_ide/scenarios/<名>.json）或直接给文件路径
# --uri 支持纯端口 / host:port / 完整 ws(s):// 地址
dart run xb_ume:run login-remote --uri 65296 --report out/login.html

# 全局 activate 后可用 `xb_ume run`：
dart pub global activate --source path .
xb_ume run login-remote --uri 65296 --continue-on-fail --shot-every-step --report out/login.html
```

常用参数：

| 参数 | 说明 |
|---|---|
| `--uri <v>` | VM service 地址：`65296` / `127.0.0.1:65296` / `ws://…/ws`，必填 |
| `--report <out.html>` | 报告路径；不指定时写到 `~/.xb_ume_ide/scenarios/reports/run-<场景>-<时间>.html` |
| `--continue-on-fail` | 失败后继续（默认失败即停，剩余步骤标 skip） |
| `--shot-every-step` | 每步都截图（默认只截失败步） |
| `--wait-after <ms>` | 步间稳定延迟（默认 700） |
| `--shots-dir <dir>` | 额外把截图 PNG 落盘 |
| `--json` | stdout 只输出一行 JSON（`ok/total/pass/fail/skip/report/results`） |
| `--list` | 列出可用场景 |

步骤语义与 GUI「自动化」Tab 一致（`tap` / `swipe` / `input` / `wait` / `back` / `navigate` / `assertVisible` / `assertRoute` / `assertInstance` / `eval` / `assertText` / `assertRequest`）；`assertLog` 依赖 GUI 的日志订阅上下文，CLI 下标为 skip 并在报告中注明。

**报告**：自包含 HTML（截图以 base64 内嵌，单文件即可作为 CI artifact 打开）——顶部结论徽章、场景/会话/起止时间/命令、总数与通过/失败/跳过、逐步表格（类型、期望、状态、耗时、实际与错误）及每步截图；失败步骤红色标注。

**退出码**（供 CI 判断）：`0` 全部通过（含 skip）、`1` 有失败步骤、`2` 参数/场景加载/连接错误。

**注意**：
- 不依赖 GUI 进程与浏览器，但仍需目标 app 处于 debug 且 VM service 可连（`flutter run` 会话有效）；
- iOS 等 `_flutter.screenshot` 不可用的平台自动退回 inspector 截图，每步约多 0.5~1s；
- 数据目录可用 `XB_UME_HOME` 覆盖（默认 `~/.xb_ume_ide`），CI 里建议显式指定 `--report` 到构建工作区。

## 二十、会话通道与能力置灰（0.9.6 起）

页头「调试会话」下拉现在会标出这条会话走的通道：

| 标注 | 含义 |
|---|---|
| `（VM）` | 只走 VM service（debug / profile，IDE 或本工具拉起的 `flutter run`） |
| `（直连）` | 只走 app 内直连服务（release 包，无 VM 调试服务） |
| `（VM+直连）` | 同一个 app 两条通道都在，工具默认走 VM |

选中会话后，当前会话做不到的功能会**自动置灰**（变暗 + 鼠标悬停说明缺什么），调试页顶部同时出现一条黄条写明「哪些不可用、哪些照常可用」。规则：

- **VM 独占**（直连会话置灰）：接入会话 / 断点（加、刷新、源码下断点）/ 调用栈 / 求值 / 底部暂停、继续、单步 / UI 重建 / 触发 GC / 泄漏检测。
- **热重载 / 热重启**：release 包（AOT）无热重载，置灰。
- **照常可用**：日志、网络、异常、时间轴、路由栈、Storage、应用沙盒、数据库、截图、点击 / 输入 / 滑动、性能采样。

> 上表是直连通道的「理论上限」。0.9.7 的 app 内直连服务只报 `inspect`；0.9.8 起报 `inspect,widgets,act,shot`（见下两节）。

实现上是声明式的：控件只加 `data-need-caps="debug|hot|gc"`，由后台下发的 `caps` 统一裁剪；旧版 daemon 不返回 `caps` 时保守全开，行为与升级前一致。

### 0.9.7：直连通道（P1 只读数据面）

app 侧可以自己起一个**只读**的 loopback HTTP 服务，让 release 包（没有 VM service）也能被读到日志 / 网络 / 异常 / 路由 / 帧数据。默认关闭，编译期打开：

```bash
flutter build apk --release \
  --dart-define=XBUME_AGENT=1 \
  --dart-define=XBUME_AGENT_PORT=47100 \
  --dart-define=XBUME_AGENT_TOKEN=<可选，长度任意的随机串> \
  --dart-define=XBUME_AGENT_APP=<可选，安卓会自动读进程名，其他平台想让下拉显示包名就填>
```

> 开关写 `=1` / `=true` 都行（内部没直接用 `bool.fromEnvironment`：它只认 `true`，写 `=1` 会静默不生效）。端口与 token 可不填，分别默认 `47100` / 不校验。

也可以代码里显式打开（测试包更方便）：

```dart
final server = await XBUme.startAgentServer();   // 默认端口 47100、只监听回环
// …
await server?.close();
```

装了带直连服务的包后，下拉里会出现 `（直连）` / `（VM+直连）` 会话，**不需要手工 adb forward**：daemon 每轮轮询会给在线设备建 `adb -s <serial> forward tcp:4711x tcp:47100`（鸿蒙走 `hdc fport`），主机端口按设备稳定分配在 `47110~47149`。

P1 能用的（`caps=inspect`）：

- 日志 Tab、异常 Tab（服务端每 2 秒轮询一次，清空后旧卡片不会复活）、Network Tab（列表 / 详情 / 清空）、时间轴 Tab（路由事件 + 网络事件）。
- 会话下拉直接选中直连会话；MCP 侧用同一份 `caps` / `transport`，能力不满足的工具会提前报错而不是连一个空地址。

P1 当时仍然置灰（0.9.8 已补齐前半）：沙盒 / 存储 / 数据库（`fs`）、点击 / 输入 / 滑动（`act`）、组件树与路由栈（`widgets`）、截图（`shot`）、性能（`perf`）、断点 / 求值 / 单步（`debug`）、热重载（`hot`）、GC。

### 0.9.8：直连通道（P2 组件树 + 动作面）

直连会话现在能**截图、找组件、点击、输入、滑动、跳页面**，验收标准就是「release 包上能看图点击」——AI 只看截图 + `xbume_find_widget` 的 `ref` 就能驱动真机，不需要 VM service。

| 能力 | GUI | MCP 工具 |
|---|---|---|
| 截图（`shot`） | 「截图」Tab 真正可用（`/api/screenshot` 直连时 app 内光栅化回 PNG） | `xbume_screenshot` |
| 组件树（`widgets`） | 「Widget 树」Tab（`/api/wtree` 直连时 app 内遍历 Element 树） | `xbume_find_widget` |
| 点击 / 输入 / 滑动（`act`） | ——（GUI 无对应面板） | `xbume_tap` / `xbume_input` / `xbume_swipe` |
| 跳页面（`act`） | ——（GUI 无对应面板） | `xbume_navigate`，回包带当前路由名 |
| 日志 / 网络 / 异常 / 时间轴（`inspect`） | 对应 Tab | `xbume_console` / `xbume_network*` / `xbume_exceptions` / `xbume_timeline` |

直连下仍然置灰的：

- **路由栈 Tab**：按 `route:stack` 键置灰。栈详情（Route 类型 / 参数类型 / isPresent）读的是 `NavigatorState._history`，`navigator.dart` 私有字段，只有 VM eval 拿得到。直连侧只给「路由事件流」——当前路由名靠 `/v1/routes` 事件重放算出来，足够 `xbume_tap` / `xbume_navigate` 回包与场景的 `assertRoute` / `back` 使用，但拿不到栈里每个 Route 的类型信息（想看历史就去时间轴 Tab）。
- **自动化 Tab**：按 `act,debug` 置灰。点击/输入本身直连能做，但这个面板的后端是 VM eval 驱动的场景录制/回放，一并置灰更诚实；命令行 `dart run xb_ume:run --uri http://…` 与 `xbume_scenario_run` 已经能跑直连会话。
- **沙盒 / 存储 / 数据库（`fs`）**、性能（`perf`）、断点 / 单步 / 求值（`debug`）、热重载 / 热重启（`hot`）、GC / 泄漏检测：release 物理上做不到。

实现要点（想改这块时先看这两条）：

- 工具层不写 `if (vm) … else …`：`bin/src/session/session_api.dart` 定义语义方法，VM 实现还是那套表达式，直连实现把 `/v1/*` 的 JSON **整形回与 VM 逐字节相同的原始串**（`\u0001` 分字段、`\u0003` 分行、`NO_ROOT` / `NOT_FOUND` 哨兵），所以解析代码一份到底。做不到的语义抛 `SessionApiUnsupported`，工具层转成带能力键的报错。
- 能力闸门在 `bin/src/mcp/server.dart::_callTool` 统一执行：缺能力直接 `isError` 回人话，不再等 handler 里连一个空地址才炸。

> 真机上端口转发需要 `adb` / `hdc` 可用；设 `XBUME_AGENT_PROBE=0` 可整体关掉转发探测（CI 或不想让 daemon 调 adb 时）。
